# v0.141.0 — the third ending, and the door it never had

`SERVER_CHANGES.md` item 36, in one route.

---

## What was already true

`cancel_shift` has been in `erpnext_mcp/tools/shifts.py` for many releases, and
its docstring is the clearest statement anywhere in this app of why a shift has
**three** endings and not two:

| Ending | What it says | What it writes |
| --- | --- | --- |
| open | the crew is still working | nothing yet |
| `end_shift` | the crew worked | a §112.161(b) attestation, and one Attendance row per crew member |
| `cancel_shift` | the crew did **not** work | no Attendance at all |

The tool was published on the MCP tool registry alone. Probed on 2026-08-26
against the deployed sidecar, which answers `{"version": "0.137.0"}` on
`/farmops/api/health` with no credential — a routed method answers **401** with
no credential and an unrouted one answers the sidecar's own **404**:

```
  POST /farmops/api/mobile/end_shift             401
  POST /farmops/api/mobile/clock_out_worker      401
  POST /farmops/api/mobile/log_shift_break       401
  POST /farmops/api/mobile/get_crew_overview     401
  POST /farmops/api/mobile/list_field_boundaries 401
  POST /farmops/api/mobile/cancel_shift          404   ← the whole of item 36
```

There was no `mobile_api.cancel_shift` and no `Route("/mobile", …)` for it, in
the deployed release or in the source tree beside it. `MobileAPI.cancelShift`
was bound in the app the whole time and the crew drill-down's long-press menu
offered **Cancel Shift** against it; `ShiftAPI.CancelUnavailable` is the sentence
a foreman got instead.

## Why the missing route cost money rather than convenience

A shift that was formed and then not worked — weather turned at 06:40, the block
was not ready, the sprayer never arrived — has exactly one correct ending, and it
was the one a phone could not reach. What a foreman standing in the yard could
actually do was:

- **Leave it open.** The weather sweep walks it for ever, `list_shifts` reports
  it as work in progress, and — the expensive part — its whole crew is held off
  every other roster, because `start_shift` refuses a second open shift for the
  same person. One forgotten Tuesday costs a crew their Wednesday.
- **Close it with `end_shift`.** That files an FSMA §112.161(b) attestation that
  a day happened and writes an Attendance row per crew member for a day nobody
  worked.

Both are wrong, one of them silently, and the silent one is the one that looks
like tidying up.

## What this release adds

One wrapper and one route:

```python
POST /farmops/api/mobile/cancel_shift
     shift | farm_shift           the Farm Shift docname
     cancellation_reason | reason required — the tool's own refusal, not the wrapper's
     cancelled_at                 defaults to now; earlier than the start is refused
     foreman_notes                optional
```

**Dispatch-gated, beside `end_stale_shift`.** This ends a shift a whole crew is
rostered on, and a picker cannot call off the crew they are standing in. It is
the gate the drill-down that draws the button is already behind, so the row is
offered to exactly the accounts the call will accept.

**Nothing is relaxed on the way through.** Every refusal the tool makes —
already cancelled, already CLOSED by a signed review, no reason given, cancelled
before the shift started — is a sentence worth putting in front of a foreman
verbatim, and the client shows all four. The missing reason in particular is
**not** pre-empted in the wrapper: the tool's sentence is about the decision
("a bare Cancelled flag is a gap somebody will be asked about"), and a wrapper
that answered "cancellation_reason is required" first would replace it with the
worse one.

**Both alias spellings are declared**, for the reason `end_shift` declares
`farm_shift`: `routes.bind` reduces a request body to the keys the signature
DECLARES, so an undeclared alias is dropped before any guard sees it and the
call comes back saying the argument was required while it sat in the body. The
two shift spellings disagreeing is refused rather than resolved, by
`_one_spelling` — one of them names a shift that is not being called off, and
nothing in the body says which.

**No client release is needed.** `ShiftAPI.cancelShift` degrades on a 404 and on
nothing else; a `ToolError` already arrives as an HTTP 400 and is shown verbatim.
The day this route is deployed, the app calls it.

## Tests

`tests_standalone/test_ios_contract.py` — `test_58_*`, five tests. The mirror is
`UndecodedResponseModel` rather than a struct because `ShiftAPI.cancelShift`
calls `FrappeClient.callVoid` and the sheet dismisses on the HTTP status; a
mirror that invented a struct would assert a contract neither side has. What the
tests assert instead is the pair of facts that make this a different ending
rather than a second close:

- `test_58_cancel_shift` — the Attendance register does not grow by one row, the
  crew rows are kept, and `end_datetime` is set so the shift stops being Active.
  Asserted as a **delta** on the register, because the fixture site carries
  Attendance of its own and an absolute zero would have been vacuously true only
  on an empty one.
- `test_58_a_missing_reason_is_the_tools_own_sentence_and_not_the_wrappers` — the
  refusal names the decision. It asserts the sentence and not the post-refusal
  document state, because a refused mobile call rolls the whole transaction back.
- `test_58_the_two_shift_spellings_disagreeing_is_refused`.
- `test_58_the_alias_the_dispatch_surface_already_speaks_is_accepted`.
- `test_58_a_field_worker_may_not_call_off_the_crew_they_stand_in`.

`tests_standalone/test_farmops_api.py` — the route joins `TheSurfaceIsClosed`'s
`EXPECTED` and `TheNewRegistersAreGated`'s `DISPATCH_GATED`, so it is driven as a
least-privileged caller and must answer the dispatch gate's own sentence. The
`len(named)` count moves 86 → 87; that assertion, and the mounted-route count
beside it, are what stop a route being mounted and classified nowhere.

`tests_standalone/test_api_mobile.py` — `cancel_shift` is in `MOBILE` rather than
`PENDING_IOS_INTEGRATION`, because `MobileAPI.swift` already names it.

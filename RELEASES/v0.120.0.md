# v0.120.0 — the label was in oxides and the prefix was invented

Farm App Retirement, Cycle 2 — the utility ports and the SQLite migration.
Cycle 1 (v0.118.0) built the doctypes that replace the sidecar's remaining
tables. This moves the code that computes things and the data that fills them.

Seven modules, one migration engine, one script, eight test modules, 257 tests.
**No new tool, no new DocType, no new column, no change to any existing file.**
Every path in this release is a file that did not exist before it, which is the
whole reason it could be built while six other sessions were working in the same
tree.

---

## The one idea

The farm_app's utilities were not wrong because they were badly written. They
were wrong in the specific way that code goes wrong when nothing can run it: the
weather simulator called a function that does not exist in its own file, the
satellite module answered NDVI when asked for an index it did not know, and the
barcode generator invented a company prefix rather than admitting it had none.

None of those were caught, because each was tangled with a database session, an
HTTP client or a Flask app context — so the half that held the errors could not
be exercised without the half that needed a server.

Every port here separates them. The decision is a function of its arguments; the
fetching and the writing are somewhere else. That is why this release has 257
tests for what the plan estimated as "XS — pure function port".

## What each module refuses to do

The interesting content of this release is negative. Each module has one thing
it will not do, and in five of the seven that thing is what its ancestor did.

| module | what it refuses |
|---|---|
| `bbch.py` | Read `2026-08-01` as growth stage 20. A stage column is free text and holds dates. |
| `gs1.py` | Invent a company prefix. `DEV123` is unscannable; a plausible numeric fallback is another company's product number. |
| `ndvi_anomaly.py` | Compute a relative drop against a baseline with no canopy, or alert on a block that is supposed to be yellowing. |
| `nutrient_calcs.py` | Report a label's P₂O₅ figure as elemental phosphorus. It is 2.3× too high, on the nutrient with the discharge limit. |
| `data_privacy.py` | Leave a list of empty worker records where a crew was. Three empty dicts still say three people. |
| `simulation.py` | Produce a yield-impact percentage. Its ancestor had `-(frost_days*5 + heat_days*3)` with no citation, and a number like that gets quoted in an insurance claim. |
| `satellite.py` | Answer NDVI when asked for `"nvdi"`. |
| `farm_app_migration.py` | Turn an MRL research session that found nothing into an MRL Record of zero. |

## The oxide trap

A fertiliser grade `10-20-10` is 10% nitrogen, 20% **P₂O₅** and 10% **K₂O**. The
first figure is elemental and the other two are oxides — for historical reasons
nobody defends and everybody follows.

```
  200 lb/acre of 10-20-10

  what the bag says          what the plan needs
  ─────────────────────      ──────────────────────────
  N       20 lb/acre    →    N        20 lb/acre   (same — N is already elemental)
  P₂O₅    40 lb/acre    →    P      17.46 lb/acre  (× 0.4364)
  K₂O     20 lb/acre    →    K      16.60 lb/acre  (× 0.8301)
```

`nutrients()` returns both bases, named, because both readers exist: a state
nutrient-management form is written in oxide, and an agronomist balancing crop
removal wants elemental. A single number labelled `phosphorus` is read as
whichever one the reader expected, and one of them is wrong by a factor of 2.3.

**What could not be read is reported, never counted as zero.** `aggregate()`
returns an `unaccounted` list with a reason per application. A plan that
silently treats an unreadable label as clean under-reports, and under-reporting
is the direction that gets a farm fined.

## The prefix that will not be invented

```python
# farm_app/app/utils/gs1.py
setting = Settings.query.filter_by(key=key).first()
if not setting:
    return 'DEV123'  # Non-GS1; replace with real for prod
```

That string went onto labels. It is not digits, so the GTIN it built could not
be scanned at all — but the malformed case is the *lucky* one. A short numeric
fallback lands inside a prefix range GS1 did issue, to a real company, and the
farm ships cases claiming to be theirs.

`prefix_or_raise` refuses, and every generator goes through it. A farm without a
licence gets an error that says to get one — or uses `standard="custom"`, which
builds the same fixed-length check-digit-protected numbers from a prefix the
farm chose and reports `gs1_compliant: False` so nothing downstream can present
one to a buyer as a GS1 key.

The check digit is asserted against two published barcodes rather than against
itself, because the classic implementation bug — weighting from the left instead
of the right — is invisible on symmetric test data.

## The migration, and the two things it will not invent

`erpnext_mcp/farm_app_migration.py` is spec-driven: ten `Spec` objects, each
naming a SQLite table, the doctype it becomes, the **natural key** that makes one
of its documents unique, and a builder. `scripts/migrate_farm_app.py` is the
command line around it, dry-run by default like `seed_related_parties.py`.

**Idempotent by a natural key and never by a row number.** A device is matched
by its hardware id, a plan by name and version, a reading by device, type and
timestamp. Matching on the SQLite `id` would be easier and wrong twice over: it
is not stored on most target doctypes, and a table that was ever re-seeded has
ids pointing at different rows than last week.

**It never updates.** A document that already exists is left exactly as it is,
including when the SQLite row has changed. The sidecar is being retired, not
synchronised — after the cutover ERPNext is the system of record, and reaching
back to overwrite an operator's correction with a stale value would silently
undo work somebody did in the new system.

### `block_ticker` is not derived from a block name

`Field.block_ticker`'s own description says it is the buyer's name for the block,
unique across the company, promised to somebody outside the business, and that
**empty is the normal state**. Turning `"Block A4"` into `"A4"` would manufacture
that promise on every block at once. Tickers come only from a JSON map the
operator supplies to `--tickers`, and a ticker over ten characters is refused
rather than trimmed — a truncated ticker is a different promise from the one the
farm made.

### An MRL of nothing never becomes an MRL of zero

This is the worst failure available to the whole exercise. A research session
whose `mrl_value` is `NOT_FOUND` is refused, because zero is a real limit and the
strictest one there is: a shipment decided against it would be held for a residue
nobody exceeded.

### A Select value nobody recognises is reported, not guessed

A farm_app `participant_type` of `"co-op"` has no Market Participant option. The
row migrates, the field takes its documented fallback, and the warning says
**which value it landed on** — an earlier draft said "left blank" while writing a
value, which sends an operator hunting for an empty field they will never find.

## Two bugs this release found in its own drafts

Worth recording because both were the kind that ship green.

**A threshold converted with its series.** `exposure()` took `unit` for the
temperature series and applied it to `threshold_c` as well, so
`heat(fahrenheit_series, threshold_c=35, unit="F")` compared readings against
1.7°C and reported every hour of the summer as heat stress. The argument names
said what was right and the code did the other thing.

**A `Z` that ate a whole table.** `moment()` stripped the offset and the
microseconds and left the trailing `Z`, so every `2026-08-01T10:30:00Z` — what a
farm_app export written by `isoformat()` produces — parsed to `""` and every
reading carrying one was refused for having "no timestamp". A table of ten
thousand readings would have migrated as ten thousand refusals, each with a
message that was true and useless.

## Running the migration

```bash
docker cp farm_app.db <container>:/home/frappe/frappe-bench/
docker cp scripts/migrate_farm_app.py <container>:/home/frappe/frappe-bench/
docker exec -w /home/frappe/frappe-bench <container> \
    python3 migrate_farm_app.py --database farm_app.db --site <site> \
        --company "Orchard Meadow, LLC" --verbose
# read the plan — refusals, warnings, counts — then:
#   ...same line with --apply
docker exec <container> rm -f /home/frappe/frappe-bench/farm_app.db
```

`--table` filters the dependency order rather than replacing it, so
`--table iot_reading` alone refuses every row: the devices they point at have not
been migrated *in that run*. Use it to re-run a table after fixing its refusals,
once its parents are in.

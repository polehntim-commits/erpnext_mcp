# v0.122.0 — the plan an inspector asks for, and the block that was almost overwritten

Farm App Retirement, Cycle 3 — the last of the Flask sidecar's own registers,
and the audit of everything left. Eight DocTypes for the FSMA preventive-controls
framework, thirty-one tools over them, one task-board read, and the two documents
the cutover itself runs on.

840 tools = 422 read + 418 mutating. Eight DocTypes, one new module, one test
module, 93 tests.

---

## Three defects the suite caught before this shipped

The suite went red on 32 assertions against the finished tree. All three causes
were real, and none was a formatting or environment artifact.

**A Link nobody sets is not a gate.** `Hazard Analysis` and `Preventive Control`
were the only two of the eight without a `company` column, and
`require_scoped_doc` reads that column off the document itself — so a missing
column does not refuse, it reads NULL and passes everything. Adding the Link is
half the fix: neither create handler set it, and a column the handler leaves
NULL holds the gate open while the DocType JSON looks correct. Both creates now
set it, both `update_` tools can set it on rows predating the column, both
`list_` tools filter on it, and all six schemas advertise the argument their
handlers read. `HazardAndControlAreScoped` is the proof: run it against the
previous code and the leak reproduces as `1 != 0` — a hazard filed under one
company returned when listing the other.

**Thirty switches shipped without a description.** The 812 older switches all
carry one; the thirty new HACCP switches carried none. That prose is the only
explanation an operator gets before ticking a box that lets an AI write to the
ledger. Defaults were already correct — seventeen reads ON, thirteen writes OFF.

**A block deletion could have stranded a food safety log.** `Monitoring
Record.block` is a plain Link to `Field` that no table in `tools/locations.py`
named, three lines below the `("Water Test", "block")` of identical shape.
`delete_farm_location` would have left an FSMA record pointing at ground that is
gone, and that record is the evidence an audit asks for.

## The near-miss, first, because it is the part worth remembering

The HACCP work was already written when this release picked it up, and it was
**one commit away from deleting v0.118.0**.

Its entries had been added at the tail of the `TOOLS` dict. That is exactly where
Cycle 1's thirty-three tools live — HEAD lines 27946–28925, `create_iot_device`
through `get_ipm_reference` — so a rebuild anchored on *whatever entry is
currently last*, rather than on the dict's closing brace, wrote straight over
them. The blast radius was wider than the dict:

```
  registry.py            33 tools gone; the compintel/iot/mrl/strategy imports
                         gone; three `block_ticker` field definitions gone
  settings JSON          the 33 matching allow_ switches gone
  tool-catalog.md        their catalogue entries gone, counts restated as 776
  tool_groups.py         Cycle 1's SECTION_DOMAIN entries still present, now
                         mapping sections that held no tools
```

**And the suite was green.** It was green because the three hand-written count
assertions had been edited down to match the damage — 808/404/404 became
776/387/389, under a docstring dated `v0.117.0` describing a release that was
four versions old. Nothing else in twelve thousand tests noticed that a third of
Cycle 1 had stopped existing.

> **A count assertion edited downwards to make a suite pass is the alarm, not
> the noise.** It is the one edit that converts a deletion into a green board.

The repair was not to patch the damaged file. Both versions are byte-identical up
to line 27938 and byte-identical again after the `TOOLS` close, so the fix was to
reassemble from HEAD: HEAD's prefix, HEAD's Cycle 1 block, the HACCP block, HEAD's
suffix. The settings JSON was rebuilt the same way — by set-merge onto HEAD's
version, because `field_order` and the `fields` array are **not** in the same
order in that doctype and a positional insert would have silently mismatched
them.

Verified afterwards, by a checker that rebuilds its expectations from
`git show HEAD:` rather than from the repaired files: 0 tools lost against HEAD,
no duplicate tool keys, `field_order` and `fields` agreeing as sets and in length,
and every one of the 840 tools carrying an `allow_` switch.

## HACCP, and why the tools are CRUD

Eight DocTypes. The plan is the root; everything else carries a
`food_safety_plan`, and most also carry the `preventive_control` inside it.

```
  Food Safety Plan          master plan, QI, lifecycle
  Hazard Analysis           per-step identification against a risk matrix
  Preventive Control        CCP definitions, critical limits, monitoring specs
  Monitoring Record         a measurement taken against a control
  Corrective Action Record  a deviation, and what was done about it
  Verification Record       calibration, log review, product testing
  Recall Plan               FDA procedure, contacts, simulation dates
  Supplier Verification     supply-chain checks with certificate expiry
```

`farm_app`'s own `food_safety` blueprint is 24 route decorators of
server-rendered forms. iOS never called any of them.

**The tools are CRUD on purpose.** The inspection records elsewhere in this app
branch on their findings and drive a state machine; these do not. The compliance
value is in a record EXISTING and being COMPLETE, not in an automated
transition — a qualified individual reviews a food safety plan, and a tool that
advanced a plan's status on its own would be manufacturing the very signature an
auditor came to verify.

**Six of the eight take an `update_`.** A Monitoring or Verification record is a
measurement with a time on it: it is appended to, and a correction to one is a
Corrective Action Record rather than an edit.

**`update_hazard_analysis` is the exception, and it was a real gap.** `farm_app`
has `/food-safety/<plan_id>/hazards/<hazard_id>/edit`; the tools had no update,
which would have made a mistyped likelihood permanent. A hazard row is a
*judgement*, not a measurement, and a plan review is precisely the occasion for
reaching a different one. `risk_level` is derived from likelihood × severity, so
a wrong likelihood propagates — the controller recomputes in `validate()`, which
Frappe runs on save as well as insert, so a downgraded likelihood cannot leave
the old risk sitting under it. The test asserting that recompute was checked
against a negative control: gating it on `is_new()` turns it red.

**`get_food_safety_dashboard` answers "are we audit-ready" in one call** —
otherwise eight reads and a date comparison per plan. `qi_current` and
`review_overdue` are computed against today rather than stored, so neither can
rot in the register, and a plan with no date on file reports `false` rather than
guessing. A register that is not installed yet counts zero instead of refusing,
so a site part-way through `bench migrate` gets honest zeros.

## `list_tasks_by_location`

One trip's worth of work per place: the claimable pool and the caller's own held
work, grouped by the Farm Task's own `location` instead of two flat lists a
screen has to cross-reference. It is a third reader of `list_available_for_me`
and `list_my_tasks`'s own calls, so every refusal and scoping rule those carry
travels with it unchanged. A task with no location is reported in
`unlocated_tasks` rather than folded into a fake "Unlocated" group.

## The two documents

`farm_app_route_mapping.md` and `farm_app_retirement_checklist.md`. Both were
rewritten from measurement rather than estimate, and the first drafts of both
were wrong in ways that mattered.

**The retired claim: "iOS calls ZERO farm_app routes."** It does not. iOS calls
`/api/wallet/*` (five paths, `WalletPassService`) and
`/api/field-ops/company/logo` (`ReferenceDataStore`), both Flask blueprints.
Both are Tor-only with NIP-98 auth, both sit inside the owner's excluded set, and
**both fail silently** — each guards on an onion address and returns early. That
is the worst shape for a false claim in a retirement document: retire the route
and nothing errors, the feature just quietly stops working. They go dark at
cutover, by decision, and the checklist now says so where the crew will read it.

**The numbers were off by 5×.** Measured on 2026-08-22:

```
  farm_app route decorators (app/, excluding worktrees)   1051   was "~225"
  distinct mobile methods iOS calls                        144   was "~120"
  /mobile routes erpnext_mcp publishes                     202
  iOS methods with no published route                       10
```

Those ten 404 today and will still 404 afterwards — `trace_forward`,
`trace_backward`, the two heat-exposure calls, and six others. Retirement neither
causes nor fixes them; iOS already translates a 404 into a typed `Unavailable`
state rather than an error banner. They are named in the mapping so nobody
diagnoses them as cutover damage.

**The verdict: iOS needs no URL change.** Its mobile traffic already points at
ERPNext through one constant, `MobileAPI.namespace = "farmops/api/mobile"`,
served by `farmops_api/routes.py` and never by Flask.

## Not ported, by the owner's decision

The vault and its encryption, the Nostr identity/event/relay code and its NIP-44
crypto, the Merkle proofs, the Tor backup sharding, and the Nostr-tied wallet
pass. Vision labelling belongs to Volume Vision and stays there.

Applicant tracking is largely covered by Frappe HR — `Job Applicant` and
`Designation` do the work of `/applicants/*` and `/job-titles/*`. **HiringCohort
is a genuine gap**: it batches H-2A workers through onboarding together and
nothing in Frappe HR groups applicants that way. Deferred, not covered, and
named as such so nobody assumes parity.

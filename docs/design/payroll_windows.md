# Payroll and bookkeeping windows; the payroll calendar — design and contract

**Status: FROZEN (2026-10-03).** Tim approved. Server **v0.224.0**. No app change (the calendar tile uses
the existing `list_query` target). Everything ships OFF: a window is a person's act in the Desk, and the
calendar tile and its reminders are unticked settings.

**Money movement and filing stay human.** The AI prepares: payroll runs, GL postings, pay stubs, the NACHA
and prenote files, tax-form PDFs and the deposit schedule. Tim uploads the NACHA file to the bank and files
and pays through EFTPS, Oregon Revenue Online or the CPA. No tool here sends money or submits a return, and
`mark_tax_form_filed` (a record that a person filed) is deliberately **not** in any window.

## 1. Windows

A **window** turns a named group of tool switches on for a limited time (default **120** minutes,
1–240), through the v0.217.0 switch timer: each switch is recorded in `switch_expiry`, the 5-minute job
turns it off when time is up, and a switch that was already on by hand is left alone (it is permanent and
the window does not own it). One audit row and one security alert when a window opens, and again when it
closes.

| Window | Tools (mutating ones only — reads are on by default) |
|---|---|
| **Payroll** | `calculate_payroll`, `run_payroll_for_period`, `submit_payroll`, `post_payroll_to_gl`, `configure_payroll_accounts`, `calculate_payroll_taxes`, `render_pay_stub`, `generate_nacha_file`, `generate_prenote_file`, `generate_tax_form`, `regenerate_tax_form`, `render_tax_form_pdf`, `bulk_render_tax_form_pdfs`, `generate_1099_prefill` |
| **Bookkeeping** | `create_journal_entry`, `submit_journal_entry`, `bulk_submit_journal_entries`, `create_purchase_invoice`, `submit_purchase_invoice`, `create_sales_invoice`, `submit_sales_invoice`, `create_payment_entry`, `submit_payment_entry`, `receive_payment` |

Only tools that exist on the site and are mutating are opened; the answer lists what opened, what was
already on, and what the group names that this site does not have. The groups are data: the JSON setting
**`switch_windows`** may add or replace a group (`{"payroll": [...], "bookkeeping": [...], "<name>": [...]}`),
and a group can never include a tool in the credential tier (`switch_catalog`).

**Surfaces.** Desk: ERPNext MCP Settings → **Open a window** (System Manager) → choose the group and the
minutes. Whitelisted method `erpnext_mcp.api.switches.open_window`. `list_mcp_switches` shows each open
switch's `expires_at`. **No MCP tool can open a window.**

**Not built, named here.** Form **940** and **W-3** are not generated by `generate_tax_form` today
(`get_futa_summary` carries the 940 figures; W-3 is the sum of the W-2s). Agricultural employers whose
workers are farmworkers file **943** annually instead of 941 — the calendar says so.

## 2. The payroll calendar

A server-driven tile **Payroll calendar** (surface `today`, audience HR Manager / HR User / System
Manager / Accounts Manager), target `{"kind": "list_query", "query": "payroll_calendar"}` — the phone
already renders list queries, so no app change. Seeded **disabled** behind the setting
**`payroll_calendar_enabled`** (off).

Rows (next **60** days and anything overdue and not filed), each `{name, title, subtitle, due_date, state}`:

| Kind | Source |
|---|---|
| Federal tax deposit (941 / 943 withholding + FICA) | `get_tax_deposit_schedule` — semiweekly or monthly per the lookback, holiday-shifted |
| Oregon withholding deposit | follows the federal schedule (same rows, named) |
| Quarterly returns: 941, Oregon OQ + Form 132 | `_state_deadlines` (last day of the month after the quarter) |
| FUTA deposit | quarterly when the year's undeposited FUTA exceeds $500 (`get_futa_summary`) |
| Annual: W-2 / W-3, 940, 943, 1099-NEC, Oregon WR | 31 January (next business day) |

`state`: `overdue`, `due` (within the reminder lead), `upcoming`, or `done` when a matching Tax Form is
marked Filed. Badge: overdue + due, tone critical when anything is overdue.

**Reminders.** A daily job (with the setting **`payroll_reminder_days`**, default `7,1`) emails each
payroll person (HR Manager and System Manager holders, or **`payroll_reminder_recipients`**) once per item
per lead, and pushes to their phones. Never sends money or files anything.

## 3. Surfaces

MCP tools +1: `get_payroll_calendar` (read). Settings: `switch_windows` (JSON), `payroll_calendar_enabled`
(0), `payroll_reminder_days` ("7,1"), `payroll_reminder_recipients`. Desk method `api.switches.open_window`
and the settings button. Tile query `payroll_calendar`; tile `payroll_calendar` seeded. Daily job
`payroll_calendar.send_reminders`.

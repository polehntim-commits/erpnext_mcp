**Deploy: v0.318.0 — deploy verification as MCP reads**

**No migrate.** Tools: **1,148 → 1,150** (two reads, on by default).

**What changed**
- **`get_deploy_status`**, this site, read-only, no shell:
  - the erpnext_mcp version;
  - the git commit — from the image's build record (`/tmp/.erpnext_mcp_head.json`, written by the Dockerfile), else
    the app's `.git`;
  - patches in `patches.txt` that the Patch Log has not applied;
  - app doctypes whose JSON is newer than the database (`migrate_needed`);
  - this worker's start time and the scheduler's last job;
  - the phones' public `/farmops/api/health`, which proves Funnel → farmops-fwd → sidecar in one probe.
- **`run_post_deploy_check`** (`expected_version`, `expected_commit`): the deploy file's checklist as one call, each
  check pass / warn / fail — version and commit, migrate, health, scheduler, pay settings in force, dangerous write
  switches on, PDF rendering, backups. Phone checks (4e) stay on a device.
- **`get_backup_status`:** each box now says `kit_expected` (2026-10-07.8) and `kit_outdated`.

**After each deploy, on each server**

`run_post_deploy_check expected_version=<version> expected_commit=<server main commit>`. A `fail` names what didn't
land. The SSH commands in the deploy file stay for the deploy itself; the checks no longer need SSH.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.318.0`, then `bench --site frontend migrate` and restart.

**Deploy: v0.237.0 — daily equipment checks: the operator checks the machine (decision 33)**

**Migrate needed**: one Farm Task Template field (Daily Check), one settings switch, and three seeded templates. No
new tools, no app change (the check is an ordinary task on FarmOps 0.38.8). **umbrel.local only.** Apply after
v0.236.0.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.237.0"`), build the fafo-erpnext image.

**2. Server, over SSH to umbrel.local**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate 2>&1 | grep -i "daily check"
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect "daily check templates seeded: Daily equipment check, Daily check add-on — Tractor, Daily check add-on — Mini
Excavator (off until …)" and `__version__ = "0.237.0"`.

**3. Turn it on and check**

1. Desk → Farm Task Template: the three templates, each with Daily Check = Start of Day; the add-ons carry their
   asset types. Edit the items to match your SOPs (they are data).
2. Desk → ERPNext MCP Settings → tick **Daily Equipment Checks**.
3. Make a task with Asset = a Mini Excavator (or set an asset's type to Mini Excavator), claim and start it on the
   phone: a new task "Daily check — <asset>" appears for that worker with the base items then the excavator items;
   the start is not held up. Start a second task on the same machine the same day: no second check.
4. A task with no asset raises no check.

**4. Rollback**

Untick the switch — nothing more is raised. The templates and any checks already raised stay.

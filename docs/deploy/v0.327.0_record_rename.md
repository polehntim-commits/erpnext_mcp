**Deploy: v0.327.0 — rename records through MCP (a cabin and its tag together), occupied kept in step, duplex rooms**

**Migrate**:
- Housing Unit and Asset Register gain `old_names`, `door_label` and `room_labels`;
- Housing Assignment gains `room`;
- no new switch: a real rename needs `allow_record` and the type's own update switch (`allow_update_housing_unit`, or `allow_update_document` for registers without one).

Tools: **1,153 → 1,153**. There is no new tool: `record` gains `action=rename`, and `list_housing_units`,
`update_housing_unit` and `create_housing_assignment` gain arguments.

**Why**

Tim (2026-10-13): "Code tool please, via MCP all the way."
- The Mill Creek cabins were registered from the phone as MC-CABIN-6&6, 16&17 and 18&19, but the doors say 5&6,
  16&16 and 18&18.
- Nothing could rename them: `update_housing_unit` refuses a new name, because the record ID is built from it.
- MC-CABIN-6&6 and 1&2 show Occupied on their asset tag and not on the unit. When the tag was created, its occupied
  box was set to "has beds" instead of the unit's own answer.

**What changed**
- **`record action=rename`**
  - Frappe's `rename_doc` moves the record, and every link, attachment, photo, print job and timeline entry follows.
  - **A dry run is the default.** It shows each link that would move, the paired record, printed tags and the order.
    `dry_run=false` renames, and needs that type's update switch (`allow_update_housing_unit` for cabins).
  - **A Housing Unit and its Asset Register tag are renamed together.** Naming either one renames both, `unit_name`
    follows, and the pair is kept.
  - **The old name is kept in `old_names`.** `universal_scan` still resolves it, so a tag or note with the old name
    lands on the record, and the result says `renamed_from`.
  - **Refused:** a name already taken (it never merges), a submitted or cancelled document, and the money, HR and
    security records.
  - **Batches:** `renames=[…]` runs in an order that avoids collisions; a swap goes through a temporary name. The whole
    batch is checked before anything changes.
  - **Printed tags:** a record whose tag was printed is listed under `needs_new_tag`, and `queue_reprint=true` queues
    a new one.
  - Each record's timeline says "Renamed from …", and the call is an MCP Action Log row.
- **Occupied:**
  - a new tag takes the unit's occupied, not "has beds";
  - saving either the unit or its tag moves the other;
  - `list_housing_units mismatches_only=true` lists the units whose tag disagrees;
  - `update_housing_unit sync_occupancy_from=unit|asset|assignments` (`unit='*'` or `units=[…]`; dry run unless
    `dry_run=false`) fixes them.
- **Duplex rooms:**
  - `door_label` holds what is painted on the door ("16&16"), and `room_labels` lists the rooms ("16a, 16b");
  - both are on the unit and its tag, and are set by `update_housing_unit` or during a rename;
  - `create_housing_assignment room=16b` must be one of the unit's rooms.

**After deploy (the user applies these; nothing is written to OML by this release)**

1. `run_post_deploy_check expected_version=0.327.0`, then `bench --site frontend clear-cache`.
2. Check that ERPNext MCP Settings has Record and Update Housing Unit ticked.
3. Dry run, then rename:
   `record action=rename type=housing_unit renames=[{"name":"MC-CABIN-6&6 - MC","new_name":"MC-CABIN-5&6"},
   {"name":"MC-CABIN-16&17 - MC","new_name":"MC-CABIN-16&16","door_label":"16&16","room_labels":"16a, 16b"},
   {"name":"MC-CABIN-18&19 - MC","new_name":"MC-CABIN-18&18","door_label":"18&18","room_labels":"18a, 18b"}]`.
   Read the dry run (links, printed tags), then add `dry_run=false` (and `queue_reprint=true` if tags were printed).
4. Occupied: `list_housing_units mismatches_only=true`, then
   `update_housing_unit unit='*' sync_occupancy_from=<unit|asset|assignments>`. Dry run first, then `dry_run=false`.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.327.0`, then run `bench --site frontend migrate` and restart. No phone
update is needed. The phone keeps showing the unique name until the door label is shown in a later app.

**Rollback**

Roll back to the v0.326.0 image. Renamed records keep their new names, and the new columns stay unused.

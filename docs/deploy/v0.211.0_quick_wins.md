# Deploy: quick wins from Tell the Farm (server v0.211.0, app 0.23.0)

Contract: `docs/design/quick_wins_2026_10.md`. Five notes from OML (AFB-2026-00015, -00019,
-00021, -00026, -00028, and the receipt fix behind -00029).

## 1. Server

1. Push `erpnext_mcp` `main`; build the image at the commit that carries
   `__version__ = "0.211.0"`. No new Python packages.
2. `bench --site <site> migrate`. Expect:
   - three fields on Accident Report (`latitude`, `longitude`, `location_accuracy_m`);
   - `staged_users` and the `Staged` status on Extraction Config;
   - one line: *seeded phone configuration wizard:accident_investigation@2 as Published* —
     "Report an Accident" with the optional map pin. If the site had already edited that
     wizard nothing is published; if no phone holds the roles yet it is left as a Draft
     and a line says so.
   - **Nothing is published for receipts.** Receipt@1 stays in force until §3 below.
3. ERPNext MCP Settings — for §3, tick `allow_update_extraction_config`,
   `allow_stage_extraction_config`, `allow_publish_extraction_config`
   (`preview_extraction_config` is a read).

## 2. App

Push `fafo_ios` `main`; build **0.23.0**. Items 1 (the two built-in report screens), 2, 3
and 5, and the phone half of 4, need this build — the phones on OML are still on 0.20.1,
so until it is installed the only changes anyone sees are the server-side ones: the wizard
v2, item search by code, and course handouts / certificates through routes the old app
does not call.

## 3. Receipt@2 — draft, preview, stage to yourself, publish (over MCP)

Receipt@2 only changes what a phone does on **app 0.23.0 or later** (older apps ignore the
`receipt` block and keep their built-in reader). Stage it after that build is on your phone.

```
update_extraction_config
  document_type: "Receipt"   from_builtin: true
  notes: "AFB-2026-00029: Home Depot total read from the Pro Xtra spend line"
→ Receipt@2, Draft

preview_extraction_config
  validation: "<the Document Validation of EXR-2026-0018, or any stored Receipt validation>"
  version: "2"
→ extracted.amount should be "626.94"; diff shows amount 1937.0 → 626.94

stage_extraction_config
  document_type: "Receipt"   version: "2"   users: ["<your login>"]
→ Staged: your phone is served Receipt@2 at its next capture; everyone else keeps Receipt@1

  …photograph a receipt or two on your phone; check total, merchant, line items…

publish_extraction_config
  document_type: "Receipt"   version: "2"
→ Published; Receipt@1 Superseded
```

To find a stored validation: `query_doctype` on **Document Validation** with
`{"document_type": "Receipt"}`. To back out before publishing, stage with a different
version or leave it — a Staged version reaches only the accounts named.

## 4. What to check after

- **Incident location:** Desk › Accident Report shows Latitude / Longitude on a report filed
  from app 0.23.0 (or from the wizard's map pin).
- **Asset documents:** attach a PDF to 40-WM-SE in Desk (or with `attach_asset_document`);
  on app 0.23.0 it is under **Documentation** on the asset and on its scan result, and
  opens with no signal once it has been opened once.
- **Class PDFs:** attach a handout to a Training Type in Desk; Training › Courses › that
  course lists it. Today › My training › Class papers lists every class.
- **Inventory:** the stock ledger and the receive / issue form show "PROWLER Place Pacs
  (22 × 3 oz)" with `PROWLER®` beneath, not the code alone.

# Deploy: v0.218.0 — device keys, phase 1 (OFF by default)

Contract: `docs/design/device_client_enrollment.md`. App: 0.28.0 (the phone side).

## Deploying

1. Build at `__version__ = "0.218.0"`; `bench --site <site> migrate`. Expect: a new doctype **Farm
   Access Token** (System Manager only), new read-only columns on Mobile Device Enrollment, and a
   "Phone sign-in (device keys)" section on ERPNext MCP Settings with **Device keys enabled OFF**
   and **Allow legacy phone secrets ON**.
2. Restart all workers and the sidecar.
3. Nothing else changes: every phone and login card works as before.

## Turning it on (after the cutover; Tim's decision)

1. Install app 0.28.0 on the phones.
2. ERPNext MCP Settings → tick **Device keys enabled**. Leave "Allow legacy phone secrets" on.
3. Each phone, next time it opens (cellular, Tailscale off): one Face ID prompt — it moves to keys.
   `list_access_inventory` shows it `key_bound: true`, `approval_method: upgraded`.
4. New phones: turn on `allow_issue_enrollment_link`, run `issue_enrollment_link` for the person, show
   the QR; the phone scans it, Face ID, done. The QR is dead after one use or 10 minutes.
5. When `list_access_inventory` says `ready_to_disable_legacy_secrets: true`, untick **Allow legacy
   phone secrets**: old login cards stop working.

## Check

- From outside: `curl -s https://<host>/farmops/api/enroll/anything` → plain text "Farm Ops sign-in
  code" (only when enabled; otherwise the uniform 401 JSON).
- `get_security_status` / `list_access_inventory`.

## Undo

Untick **Device keys enabled**. Phones that moved to keys then cannot sign in until it is ticked again
(their secret was destroyed on purpose) — issue them a login card if needed.

# Deploy: v0.228.0 — the doorway walk and detector test; scanning with no signal (app 0.35.0)

Code plus one migrate (three columns each on Housing Inspection and Detector Test). Three new phone
routes. No settings, no MCP switches.

**Test on umbrel.local only.** Not OML.

1. Build at `__version__ = "0.228.0"`; `bench migrate`; restart workers. Ship app 0.35.0.
2. Check the migrate: Housing Inspection and Detector Test have a collapsed **Filed from a phone** section
   (Request ID, Done on the phone at, Received by the server).
3. As a Foreman: Housing → a cabin → walk it, take before/after photos. **Force-quit** mid-walk and reopen
   the cabin: the ticks, notes and photos are still there.
4. Airplane mode → **File this inspection**: "Saved on this phone". Settings → Waiting to sync shows
   Housing walk and Detector test. Back online: both send by themselves (or Sync now); the Desk shows the
   walk with its photos, dated by the phone, and the Detector Test (a failed / missing detector raises its
   replacement Farm Task as before).
5. Upload resume: start a walk with several large photos, file it, and turn airplane mode on mid-send.
   Back online, it continues — the server log shows only the missing pieces arriving.
6. Scanning with no signal: On this phone → **Prepare for offline** (now also "N tags for scanning").
   Airplane mode → scan an asset tag or a cabin's QR: the card opens with "No signal — showing what this
   phone saved <time>" and its open tasks. A tag scanned online before shows its full history too.

**New routes**: `create_housing_inspection`, `create_detector_test` (Foreman or above; idempotent on
`client_request_id`; `tapped_at` dates the record), `get_offline_scan_pack` (the caller's entities). 188
mobile methods.

**Rollback**: additive columns. App 0.35.0 against an older server: the walk and test fail to send (404) and
wait in Settings with Retry; scans fall back to the old live-only behaviour.

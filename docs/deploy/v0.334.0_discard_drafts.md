**Deploy: v0.334.0 — Discard for draft Journal Entries (with Bank Bridge 1.0.11)**

**Migrate**: Journal Entry gains five Custom Fields (discarded, discard reason / by / at, duplicate of); new doctype
Discarded Draft Log; two Client Scripts on Journal Entry (list, form). Tools: **1,156 → 1,159**. Setting
`discard_auto_purge_days` (0 = off). Bank Bridge 1.0.11 after the server.

**Why** (Tim): "Yah lets do a discard please so its less confusing."

**What changed**
- A draft can be Discarded: kept, recoverable, out of bulk submit, draft counts and the default Journal Entry list.
- Restore puts it back. Purge (System Manager / Accounts Manager) deletes discarded drafts for good, logging each.
- Bank Bridge stops counting discarded drafts, and does not re-draft a purged duplicate (Allow Recreate on its log
  row releases it).

**After deploy (Tim; nothing was written to OML by this release)**

1. ERPNext MCP Settings: tick Discard Draft Journal Entries and Restore Discarded Draft (List Discarded Drafts is
   on). Leave Auto-purge at 0 until you have used Purge by hand. Reconnect the MCP client.
2. Desk → Journal Entry list: discarded drafts are hidden; the Show / hide discarded button brings them back.
3. Over MCP, set aside known duplicates (dry check first with list tools), e.g.:

```sh
get_journal_entries from_date=2026-01-01 to_date=2026-12-31 docstatus=draft company="<company>"
discard_draft_journal_entries names=["<ACC-JV-…>"] reason="duplicate settlement leg" duplicate_of="<the one that stays>"
list_discarded_drafts company="<company>"
```

4. Bank Bridge `get_draft_health` now reports `discarded_count` beside `draft_count`.

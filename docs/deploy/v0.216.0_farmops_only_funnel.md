# Deploy and cutover: Farm Ops over `/farmops/api` only (server v0.216.0, app 0.27.0 build 9)

Contract: `docs/design/farmops_only_funnel.md`. Security review 2026-10-02, finding C1.

**Nothing in this release changes what is public.** Deploying it is safe on its own: with the two
new settings untouched, every card, tag and phone behaves exactly as on v0.215.0. The Funnel
changes are part C, and they are Tim's to run.

## What the audit found

- The app calls only `<base>/farmops/api/...`. No `/api/method`, `/api/resource`, `/files`,
  `/private/files` — files come back as bytes inside sidecar answers.
- OML's login card says `https://orchardmeadow-umbrel.tail2b0bb0.ts.net/erpnext`, so the phone
  reaches the sidecar *through* the public `/erpnext` mount.
- On OML today `https://orchardmeadow-umbrel.tail2b0bb0.ts.net/farmops/api/health` answers
  Tailscale's 404: **`/farmops` is not on the public Funnel yet.** Step C2 adds it.

## A. Deploy the server (code + one migrate)

1. Push `erpnext_mcp` `main`; build the image at the commit with `__version__ = "0.216.0"`.
2. `bench --site <site> migrate`. Expect: two fields on ERPNext MCP Settings (Farm Ops Public URL;
   Allow legacy /erpnext paths for phones, ticked) and one on Mobile Device Enrollment
   (`api_base_mode`). No patch, no data change.
3. Restart the sidecar with the image (it serves the new tag page).
4. Check: `get_server_status` → `erpnext_mcp_version: 0.216.0`, and `erpnext_funnel` says
   `ready_to_close_erpnext_funnel: false` with the reason "Farm Ops Public URL is empty".

Do this on umbrel.local first. Nothing to switch on; no MCP tool switch changes.

## B. Install the app

5. Build and install Farm Ops **0.27.0 (9)** on every phone. Open it once.
   - With `/farmops` not yet mounted, it finds nothing at the host root and carries on exactly as
     before, on the `/erpnext` base. It tries the root again at most every 6 hours and on sign-in.

## C. Cutover runbook (OML host) — in this order

```bash
TS="docker exec tailscale_web_1 tailscale"
HOST=https://orchardmeadow-umbrel.tail2b0bb0.ts.net
```

**C1. Snapshot (this file is the rollback).**
```bash
$TS serve status --json | tee ~/funnel-before-$(date +%F).json
$TS funnel status
```
Read the JSON: note the target of the `/erpnext` handler (`<ERP_TARGET>`, e.g. `http://127.0.0.1:5300`)
and whether anything is mounted at `/`.

**C2. Publish `/farmops` — add before removing anything.**
```bash
$TS funnel --bg --https=443 --set-path=/farmops http://127.0.0.1:5250/farmops
```
The target must end in `/farmops`: `--set-path` strips the path it matched. `127.0.0.1:5250` is the
sidecar as the host sees it (the `farmops-fwd` forwarder, or the published port). Do **not** run
`scripts/mount_farmops_funnel.sh` for this — it also publishes the MCP endpoint and the Bank Bridge
callback at the host root, which the review wants tailnet-only.

Verify from anywhere (no Tailscale needed):
```bash
curl -s  $HOST/farmops/api/health                       # {"ok": true, "service": "farmops-api", "version": "0.216.0"}
curl -si -X POST -H 'Content-Type: application/json' -d '{}' $HOST/farmops/api/mobile/scan_asset | head -1   # 401
curl -s  $HOST/farmops/api/scan/TEST | head -3           # the "Farm Ops tag" page
```

**C3. Tell the server the phones' address** (ERPNext MCP Settings, Desk):
- Farm Ops Public URL = `https://orchardmeadow-umbrel.tail2b0bb0.ts.net` (no path).
- Leave Public URL and "Allow legacy /erpnext paths" as they are for now.

**C4. Probe.** `validate_public_endpoint` with `probe_routes: true`. Want:
`farmops_only.routes_ok: true`, `scan_page_ok: true`, and the verdict "…/erpnext must stay until
the phones move" naming Tim's phone.

**C5. Move the phone.** Either is enough:
- Open Farm Ops 0.27.0, sign out, and scan a **re-issued login card** (C6); or
- just wait/relaunch: within 6 hours of C2 the app finds `/farmops/api` at the host root by itself
  and switches. Sign-out + sign-in with the old card also switches it immediately.

**C6. Re-issue Tim's login card.** `generate_mobile_login_qr` for `polehntim@gmail.com` (the switch
is off by default — turn `allow_generate_mobile_login_qr` on, run it, turn it off). The card now
encodes `url: https://orchardmeadow-umbrel.tail2b0bb0.ts.net`. Print it on the CR80 card as before
and destroy the old one. It works on any app build. `revoke_mobile_device` the old "Login card"
device afterwards if you want the old printout dead.

**C7. Confirm the phone has moved — on cellular, Tailscale OFF.**
- In the app: open Tasks, scan an asset tag, take and upload a photo, open a label PDF.
- `get_server_status` → `erpnext_funnel.devices[0]`: `app_version: 0.27.0 (9)`,
  `api_base_mode: farmops`, and **`ready_to_close_erpnext_funnel: true`**.
- Do not go on until that flag is true.

**C8. Remove the public `/erpnext` mount; keep it on the tailnet.**
```bash
$TS funnel --https=443 --set-path=/erpnext off
$TS serve --bg --https=8443 --set-path=/erpnext <ERP_TARGET>          # tailnet only, not funneled
$TS funnel --https=443 --set-path=/ off                               # only if C1 showed a handler at /
$TS funnel status                                                     # 443 should list /farmops and nothing else you did not intend
```

**C9. Verify from cellular, Tailscale OFF.**
```bash
curl -si $HOST/erpnext/login | head -1                    # HTTP/2 404, body "404 page not found"
curl -si $HOST/erpnext/api/method/ping | head -1           # 404
curl -s  $HOST/farmops/api/health                          # still the sidecar
```
and the app still works (repeat C7's taps).

**C10. Point the MCP at the tailnet address.** ERPNext MCP Settings ▸ Public URL =
`https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443/erpnext`. Update the MCP connector URL in
Claude to the same base (or use `http://100.69.162.122:5300` as today). With Tailscale ON, run
`get_server_status` through the MCP — it answers. Then `validate_public_endpoint`
`probe_routes: true` → `farmops_only.verdict: "cutover complete…"`, `erpnext.erpnext_public: false`.

**C11. Close the door behind you.** Untick "Allow legacy /erpnext paths for phones". From then on
`generate_mobile_login_qr` refuses to issue a card on a URL with a path.

### Rollback (any step after C8)

```bash
$TS funnel --bg --https=443 --set-path=/erpnext <ERP_TARGET>
```
Phones on 0.27.0 keep using `/farmops/api`; a phone on an older build with an old card works again
at once. Nothing on the server needs undoing. `~/funnel-before-<date>.json` has every original
handler and target.

## What still needs `/erpnext` after cutover (tailnet only)

- The Desk, and the MCP endpoint.
- **Google Wallet pass images**: `generate_employee_badge_pass` gives Google an image URL under
  `public_url`. With `/erpnext` off the public Funnel, Google cannot fetch it and the Android pass
  shows no logo/photo. Apple Wallet passes embed their images and are unaffected. Not fixed here.
- Old printed tags opened with the phone's **Camera** app went to a Frappe 404 before and go to
  Tailscale's 404 now. Scanned **in the app** they work exactly as before.

## Decisions for Tim

1. The Desk field is `legacy_erpnext_paths`, labelled "Allow legacy /erpnext paths for phones":
   every `allow_*` field on that form is a tool switch and the console bulk-toggles them. It is
   reported as `allow_legacy_erpnext_paths` in `get_server_status`.
2. No universal link / URL scheme yet (contract, decision 1). `ScanLink` in the app is ready for it.
3. The app decides by asking `/farmops/api/health` at the host root, not by comparing version
   numbers: if the sidecar answers there, it is used there.

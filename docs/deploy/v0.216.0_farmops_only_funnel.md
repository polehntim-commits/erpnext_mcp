# Deploy and cutover: Farm Ops over `/farmops/api` only (server v0.216.0, app 0.27.0 build 9)

Contract: `docs/design/farmops_only_funnel.md`. Security review 2026-10-02, finding C1.

**Nothing in this release changes what is public.** Deploying it is safe on its own: with the two
new settings untouched, every card, tag and phone behaves exactly as on v0.215.0. The Funnel
changes are part C, and they are Tim's to run.

## Ground rule: every phone is a crew phone

Tim, 2026-10-02: "Assume all are crew phones." **No phone has Tailscale — including Tim's.** The app
must be fully usable through the public `/farmops/api` path and nothing else.

- **Every phone check in this runbook is done on cellular with Tailscale OFF** (or the Tailscale app
  not installed). Wi-Fi at the farm is not a valid test: it can reach things a crew phone cannot.
- Every `curl` below is run from outside the tailnet (a laptop on a phone hotspot with Tailscale off).
- Tailscale is for the office: the Desk and the MCP endpoint. It is never a step for a phone.
- The legacy `/erpnext` base is a fallback that exists only until step C8.

**The standard phone test** (referred to below as "the phone test"), signed in as a manager:

1. Tasks: open the list, open a task, complete one with a photo (upload).
2. Scan: an asset tag printed before this release, and a worker badge.
3. Files: open a label or SOP PDF, and a training card.
4. Manager: request an ID card print and see it in the print queue; open the compliance inbox and
   dismiss or rectify one alert; approve a leave request or a task step.
5. Map: the slope layer draws (tiles).
6. Settings: the server shown is the host with **no** `/erpnext`.

## What the audit found

- The app calls only `<base>/farmops/api/...`. No `/api/method`, `/api/resource`, `/files`,
  `/private/files` — files come back as bytes inside sidecar answers.
- OML's login card says `https://orchardmeadow-umbrel.tail2b0bb0.ts.net/erpnext`, so the phone
  reaches the sidecar *through* the public `/erpnext` mount.
- On OML today `https://orchardmeadow-umbrel.tail2b0bb0.ts.net/farmops/api/health` answers
  Tailscale's 404: **`/farmops` is not on the public Funnel yet.** Step C2 adds it.

## A. Deploy the server (code + one migrate)

1. Push `erpnext_mcp` `main`; build the image at the commit with `__version__ = "0.216.0"`.
2. `bench --site <site> migrate`. Expect: two fields on ERPNext MCP Settings (Farm Ops Public URL;
   Allow legacy /erpnext paths for phones, ticked) and one on Mobile Device Enrollment
   (`api_base_mode`). No patch, no data change.
3. Restart the sidecar with the image (it serves the new tag page).
4. Check: `get_server_status` → `erpnext_mcp_version: 0.216.0`, and `erpnext_funnel` says
   `ready_to_close_erpnext_funnel: false` with the reason "Farm Ops Public URL is empty".

Do this on umbrel.local first. Nothing to switch on; no MCP tool switch changes.

## B. Install the app

5. Build and install Farm Ops **0.27.0 (9)** on every phone. Open it once.
   - With `/farmops` not yet mounted, it finds nothing at the host root and carries on exactly as
     before, on the `/erpnext` base. It tries the root again at most every 6 hours and on sign-in.

## C. Cutover runbook (OML host) — in this order

**The paste-ready version is `docs/deploy/v0.216.0_cutover_paste_ready.md`** (v0.216.1): exact
`sudo docker exec tailscale_web_1 tailscale …` commands for zsh, no comment lines inside the blocks,
and the targets — sidecar `http://127.0.0.1:5250/farmops`, ERPNext `http://127.0.0.1:5300` (confirm
against the C1 snapshot). Two corrections to the v0.216.0 text that used to be here:

- the `TS="docker exec …"` variable does not work in zsh, which does not split `$TS` into words;
- C8 serves ERPNext on the tailnet port 8443 **at the root** (`serve --bg --https=8443
  http://127.0.0.1:5300`), not under `/erpnext`, so the Desk's `/assets` resolve; C10's Public URL is
  therefore `https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443` with no path.

Steps, in order: C1 snapshot → C2 add `/farmops` and verify from outside → C3 Farm Ops Public URL →
C4 probe → C5/C6 move the phone and re-issue the card → C7 phone test on cellular with Tailscale
off, until `ready_to_close_erpnext_funnel: true` → C8 remove `/erpnext` from the Funnel, serve
ERPNext on 8443 → C9 verify `/erpnext/login` is 404 from outside and repeat the phone test → C10
MCP to the tailnet address (office Mac only) → C11 untick the legacy setting. Rollback: re-add the
`/erpnext` Funnel mount with the C1 target.

## After cutover: watching the public surface

- `list_error_logs` / the sidecar log: `farmops-api auth-failure ip=… path=… key=<hash> n=…` per failed sign-in.
- MCP Action Log: a `mobile:auth_failures` row (Blocked) when one address fails 10 times in a minute,
  at most one an hour per address. Set **Drift report email** on ERPNext MCP Settings to get it by
  email too; an app can also register the `farmops_auth_alert` hook.
- The first such row also tells you whether the recorded address is the real client or the proxy
  (it is the rightmost `X-Forwarded-For` hop). If every row shows the same local address, say so —
  per-address limits are then per-proxy and need the forwarder to pass the client address.

## What still needs `/erpnext` after cutover (office, tailnet only — never a phone)

- The Desk, and the MCP endpoint.
- **Google Wallet pass images**: `generate_employee_badge_pass` gives Google an image URL under
  `public_url`. With `/erpnext` off the public Funnel, Google cannot fetch it and the Android pass
  shows no logo/photo. Apple Wallet passes embed their images and are unaffected. Not fixed here.
- Old printed tags opened with the phone's **Camera** app went to a Frappe 404 before and go to
  Tailscale's 404 now. Scanned **in the app** they work exactly as before.

## Decisions for Tim

1. The Desk field is `legacy_erpnext_paths`, labelled "Allow legacy /erpnext paths for phones":
   every `allow_*` field on that form is a tool switch and the console bulk-toggles them. It is
   reported as `allow_legacy_erpnext_paths` in `get_server_status`.
2. No universal link / URL scheme yet (contract, decision 1). `ScanLink` in the app is ready for it.
3. The app decides by asking `/farmops/api/health` at the host root, not by comparing version
   numbers: if the sidecar answers there, it is used there.
4. No short-lived download URLs were added: no file is served by URL at all (contract addendum H6).
5. `GET /mobile/login_qr_image?user=` stays as it is (HR-gated, audited); it carries an email in a URL.

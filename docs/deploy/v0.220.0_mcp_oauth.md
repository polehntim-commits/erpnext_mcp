# Deploy: v0.220.0 — OAuth 2.1 for MCP clients (OFF by default)

Rides on v0.219.0. Code plus one migrate (new settings, one switch, a `Revoked` status on Farm
Access Request, two hooks). App 0.30.0 (phones send `X-FarmOps-Authorization` as well; the AI-client
approval screen). Contract: `docs/design/device_client_enrollment.md` §6.3–§6.4.

**Deploying changes nothing.** `mcp_oauth_enabled` ships off: every OAuth path answers 404, the
`/.well-known/` renderer claims nothing, the auth hook returns at once, and the static X-MCP-Token
is the only way into the MCP, as today.

1. Build at `__version__ = "0.220.0"`; `bench migrate` (it also clears Frappe's 404 cache, which
   matters: a `/.well-known/` path probed before the deploy may be cached as 404); restart workers.
   `get_server_status` shows `"mcp_auth": {"mcp_oauth_enabled": false, …}`.

## Turning it on (Tim's decisions first)

2. Create the service user the clients will run as, e.g. `mcp-agent@<domain>`: enabled, **no
   System Manager, no Administrator**, only the roles the tools you will switch on need (the MCP
   System User's role profile is a fair start). Set **OAuth clients run as** to it.
   `get_security_status` → `mcp_oauth_user` fails while this is Administrator or a System Manager.
3. Set **OAuth issuer** to the address the AI client uses, origin only — on OML
   `https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443` (the office port, tailnet only; never
   Funnel). After the C-runbook the ERPNext site is served at the root of 8443, so `/.well-known/`
   and `/api/method/...` both reach Frappe there. Check from a tailnet Mac:

   ```zsh
   curl -s https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443/.well-known/oauth-authorization-server
   ```

   It must answer JSON whose `issuer` is exactly that origin (with OAuth still off it is a 404 —
   tick step 4 first, then check).
4. Make sure `allowed_cidrs` covers where the client calls from (a tailnet Mac: `100.64.0.0/10`).
   Tick **OAuth for MCP clients**. Leave **Keep the static MCP token working** ticked.
5. In Claude Code: add the server **without** a token —

   ```zsh
   claude mcp add --transport http erpnext-oml https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443/api/method/erpnext_mcp.mcp.handle
   ```

   then `/mcp` → authenticate. A browser page opens with a code and a QR. Approve it on a phone
   signed in to Farm Ops with Face ID (app 0.30.0: Phones → Approve, scan), or in the Desk:
   **ERPNext MCP Settings → Approve an access request** → code → *read* (or *read_farm*, or custom
   scopes). The page returns to Claude Code by itself.
6. `list_access_inventory` → `clients` shows it; `revoke_mcp_client` (switch off by default), the
   Desk method `erpnext_mcp.api.access.revoke_client`, or the RFC 7009 revoke endpoint ends it.

## Retiring the static token (later)

7. When `get_server_status.mcp_auth.ready_to_disable_static_mcp_token` is true (OAuth on, a client
   approved, 14 days tracked, no static-token call in them), untick **Keep the static MCP token
   working**. Re-tick it to undo; nothing else changes.

## What to watch

- Security Alert Recipients get: a client approved; a client revoked; **a code or refresh token
  replayed** (the whole sign-in is ended — treat as theft unless a client just crashed and retried).
- MCP Action Log rows from a client carry `oauth <request> <client> (approved by …)` in Agent Session.
- A client asking for a tool it was not granted gets "outside the scopes this client was granted";
  the `allow_` switches still apply on top.

## Rollback

Untick **OAuth for MCP clients**: every OAuth path is 404 again on the next request, every OAuth
token stops working, and the static token works. No data to undo.

**Deploy: v0.319.0 — MCP parity, part 1 (phone-only capabilities and create-only registers)**

**No migrate.** Tools: **1,150 → 1,150**. No new tools: each capability is an argument on the tool that already owns
the register, or an action on `record`. Writes stay off until their switches are ticked.

**What changed**
- **`record` gets get / list / update for 42 registers that had only a create tool.** Examples: spray tank mix,
  crop observation, IoT reading, housing assignment, farm task, scale ticket, warehouse, training session.
  - get and list run through `query_doctype`, under this account's permissions, with no Password fields.
  - update runs through `update_document`: drafts only, and every field must be on Updatable Fields.
  - `record action=types` marks these actions `generic`.
  - Money, HR, share links and security stay off `record`.
- **Phone capabilities now on MCP:**

  | Phone call | MCP |
  |---|---|
  | `find_item_by_barcode` | `get_item barcode=` (`found: false` is an answer) |
  | `add_item_barcode` | `update_item barcode=` (a code on another Item is refused) |
  | `reactivate_employee` | `update_employee reactivate=true` (hiring roles; writes status Active + today only) |
  | `link_title_to_asset` | `update_registered_asset title_receipt=` |
  | `get_break_schedule` | `get_break_policy shift=` (each break's due time; minors by band) |
  | `open_crew_tasks` | `list_dispatch_board crew_only=true` |
  | `attach_training_certificate` | `attach_file_to_document as_certificate=true` on an Employee Training Record (sets `certificate_file`; training roles, record's company) |

- **Already covered, no change:**
  - `create_farm_location`: `create_parcel` / `create_field` / `create_housing_unit` / `create_irrigation_zone`.
  - `attach_employee_document`: `commit_staged_file` plus `attach_file_to_document` (private by default).
  - `expense_account_map`: `search_accounts`.
  - `submit_app_feedback`: the phone's own channel; MCP reads and resolves it.

**After deploy**

1. `record action=types`: `farm_task` lists `generic: ["list", "update"]`.
2. `get_item barcode=<a code on the shelf>` answers `found` true or false.
3. `run_post_deploy_check expected_version=0.319.0`.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.319.0`, then `bench --site frontend migrate` and restart.

**Rollback**

Roll back to the v0.318.0 image. The new arguments go away; no data changes shape.

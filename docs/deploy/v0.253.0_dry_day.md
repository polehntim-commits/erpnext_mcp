**Deploy: v0.253.0 — probabilistic dry day, per-rule rain threshold, Holds cleared by the forecast, rain archive check**

**Migrate needed**: one settings switch (Get Forecast Verification, on), one rule seeded OFF
(`weather_check_pruning_rain`). No phone change. **umbrel.local first.** Apply after v0.252.0.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.253.0"`), build the fafo-erpnext image.

**2. Server, over SSH to umbrel.local**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate 2>&1 | grep -i "go / hold\|rain archive"
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect "rain archive check rule seeded OFF: weather_check_pruning_rain" (first migrate) and `0.253.0`. On a site that
already ran v0.240.0–v0.252.0, the pruning preset keeps the tree it was seeded with (seeding is create-only); compare
it with the new defaults below in the Desk before switching it on. Both production servers are on v0.231.2, so they
get the new defaults.

**3. Turn it on (when Tim chooses)**

1. Weather Settings → **Block forecasts for work timing** (forecast_enabled). Nothing here runs without it.
2. Desk → Compliance Rule → `go_hold_pruning_canker`: check the values, approve, enable. Defaults: the next 7 days'
   chance of a day over **0.05 in** under **40%**, dry **48 hours**, no frost (28 °F) in 2 days. Each is a number
   on the rule (`over`, `value`, the `[0..6]` window).
3. Desk → Compliance Rule → `weather_check_pruning_rain`: approve, enable — the alert when it rained in the week
   after pruning.

**4. Checks**

1. `check_go_hold` on an open pruning task: each rule's answer has `rain_forecast` (window, `over_in` 0.05,
   `risk_pct`); the reason names "Rain likely this week" or "Rained in the last 48 hours" when it holds.
2. A task on Hold for rain: when the forecast dries, the Hold clears within the hour without waiting for 06:00 (the
   task's Go / Hold log shows `forecast_refresh`, cleared). An unchanged verdict writes nothing.
3. `get_compliance_field_map`: `aggregations` lists `chance_over`; `context` lists `weather.forecast.daily[].rain`
   and `weather_check.*`.
4. A week after a pruning task completed under the rule: the 04:45 job adds an `archive_check` entry to its log
   (provisional, then final from the archive); `get_forecast_verification` shows it with the Brier score. If a day
   passed 0.05 in, `weather_check_pruning_rain` (when enabled) raises a Warning on the next sweep.

**5. Rollback**

Untick Block forecasts (everything here goes quiet), or disable the two rules. An older image ignores the new log
entries and the switch.

**Deploy: v0.320.0 — MCP parity, part 2 (the phone's remaining reads)**

**No migrate.** Tools: **1,150 → 1,150**. No new tools: each read is an optional argument on the tool that owns the
register.

**What changed**

| Phone call | MCP |
|---|---|
| `get_compliance_inbox` | `list_compliance_calendar_for_me inbox=true` (the acting user's inbox) |
| `get_field_card` | `get_field include_card=true` (open tasks, hazards, recent history) |
| `get_ipm_threshold_status` | `get_ipm_organism count= block=` (action / warning / below, options lowest impact first) |
| `update_contact_where_met` | `save_contact contact= met_at= met_on=` (no card) |
| `get_task_sops` | `get_task_with_evidence_contract include_sops=true` |
| `get_item_label` / `get_item_label_file` | `get_item include_label=true`; read a file with `get_attachment_content` |

**Already covered:**
- `set_employee_contact_fields`: `update_employee`.
- `answer_work_notice`: `send_work_notice`.
- Task and inspection evidence: `list_attachments` / `get_attachment_content` / `get_task_with_evidence_contract`.

**Kept on the worker's phone** (audit §A), because each acts on the worker's own data, signature, Face ID or
physical presence:
- direct deposit and bank verification;
- daily pay;
- SOP review;
- training sign-off and check-in;
- "label viewed";
- the worker's own work notices.

HR's reads remain: `list_direct_deposit_changes`, `list_work_notices`.

2. `run_post_deploy_check expected_version=0.320.0`.

Push and build with `ERPNEXT_MCP_VERSION=0.320.0`, then `bench --site frontend migrate` and restart.

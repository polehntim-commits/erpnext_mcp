**Deploy: v0.317.0 — OAuth sign-in and the limited MCP user, migrated safely**

**Migrate**: MCP Action Log gains `auth_method`. Tools stay at 1,148 (`list_access_inventory` gains fields). Funnel is
not touched.

**What changed**
- **Sign-in method on every call:** each MCP call records how it signed in (Action Log → Auth Method: Static token /
  OAuth), beside its client program, model, address and the person it acted for.
- **Who still uses the static token:** `list_access_inventory` now lists `static_token_callers` over the last `days`
  — client program, address, model, calls, first and last seen, and the tools used — plus `static_token`
  (last used, `ready_to_disable_static_mcp_token`).
- **Create MCP System User (from plan):** a new Desk button on ERPNext MCP Settings, System Manager only, with no MCP
  tool. It:
  - creates a System User with no password and no welcome email;
  - creates a Role Profile "MCP System User" with exactly the roles `plan_mcp_system_user` recommends (never System
    Manager or Administrator);
  - names it as the MCP System User.
  It does NOT tick Require User Context, so nothing changes until Tim ticks it.
- **Unchanged:** OAuth (v0.220.0) — client registration, approval by a person in the Desk or on the phone, 60-minute
  tokens with rotating refresh — and the static token, which keeps working while "Legacy Static MCP Token" is ticked.

**Tim's steps, in order — per server (umbrel.local, then OML)**

1. **The limited user.** In the Desk, open ERPNext MCP Settings and click **Create MCP System User (from plan)**.
   Enter `mcp@<farm domain>`. Then over MCP run `plan_mcp_system_user` with `candidate=mcp@<farm domain>` until it
   says `ready: true`. Then tick **Require User Context** in the Desk. MCP calls now run as that user, not
   Administrator. Undo: clear MCP System User.
2. **Turn on OAuth.** Tick **MCP OAuth Enabled**. Leave **Legacy Static MCP Token** ticked.
3. **Move each client, one at a time, and verify it.**
   - **Claude Desktop — `erpnext` (umbrel.local) and `erpnext-oml` (OML):**
     - In `~/Library/Application Support/Claude/claude_desktop_config.json`, keep the server URL, and remove the
       `--header` / `X-MCP-Token` argument from that server's `mcp-remote` args. Keep a copy of the file first.
     - Quit and reopen Claude. `mcp-remote` sees no token, follows the server's OAuth discovery and opens a sign-in
       page showing a code.
     - In the Desk, use **Approve an access request**, enter the code and choose the profile: `read` or `read_farm`
       for read-only, or full scopes for this desktop. Writes still follow each tool's own switch.
     - Verify: make one call, then `list_access_inventory`. The client is under `clients`, and the Action Log row
       says Auth Method = OAuth.
   - **The 3:30 AM OML brief, the 10 PM receipt processing and the other Cowork scheduled tasks:** they use the
     Claude Desktop connectors above, so they move with them. After the next run, check the Action Log rows for that
     hour show OAuth.
   - **Bank Bridge → ERPNext:** it uses an ERPNext API key and secret, not the MCP token, so nothing to move.
   - **The backup kit:** it writes a status file and never calls the API, so nothing to move.
4. **Watch.** `list_access_inventory` → `static_token_callers` should go empty. `get_server_status` →
   `mcp_auth.ready_to_disable_static_mcp_token` turns true after 14 quiet days with an approved client.
5. **Only then, with Tim's OK:** untick **Legacy Static MCP Token**. Undo: tick it again — the token itself is
   unchanged.

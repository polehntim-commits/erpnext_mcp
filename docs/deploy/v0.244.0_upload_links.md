**Deploy: v0.244.0 — one-time upload links (server only; no app change)**

**Migrate needed**: the Upload Link doctype and six ERPNext MCP Settings fields. Everything ships OFF. Four new MCP
tools — `get_upload_status`, `list_upload_links` (reads, on); `request_upload_url`, `revoke_upload_link` (writes,
off). **umbrel.local only.** Apply after v0.243.0.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.244.0"`), build the fafo-erpnext image.

**2. Server, over SSH to umbrel.local**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect `__version__ = "0.244.0"`.

**3. Turn it on (Desk → ERPNext MCP Settings)**

1. Tick **Upload Links Enabled** (the master switch; off, the route is a 404 and nothing can be issued).
2. Tick **Request Upload URL** (and **Revoke Upload Link** if wanted). The two reads are already on.
3. Leave **Upload Links: Allow Public Files** unticked (decision 48). There is no video kind (decision 47).

**4. Checks on umbrel.local** (from the Mac on the farm network)

1. `request_upload_url` with `doctype: "Governance Document"`, `name: <a test record>`, `kinds: ["document"]`,
   `max_bytes: 10000000`. The answer has a `url` ending `/farmops/api/upload/<long token>`, `expires_at` 15
   minutes out, `is_private: true`.
2. Send a ~5 MB PDF to that path on umbrel.local's FarmOps address (the one the phone uses on the farm network):
   `curl -T agreement.pdf -H "X-File-Name: agreement.pdf" -H "Content-Type: application/pdf" "<url>"`.
   Expect JSON with `file`, `file_size`, `sha256`. Desk → the Governance Document shows the PDF attached, private.
3. The same `curl` again: 404 "Not found." (used once). A made-up token: the same 404.
4. A 20 MB file on a 10 MB link: 413, and `get_upload_status` says Failed with the reason.
5. An `.mp4`, or a `.zip` / `.exe` renamed to `.pdf`: 415.
6. `request_upload_url` with `is_private: false`: refused, naming the admin switch.
7. `list_upload_links` shows the attempts; no answer anywhere contains the token.

**5. Not in this deploy**

The OML Operating Agreement upload is a separate step for Tim to approve; nothing here touches OML.

**6. Rollback**

Untick **Upload Links Enabled** — the route answers 404 and nothing can be issued. An older image ignores the doctype
and the settings fields; files already uploaded stay attached.

**Deploy: v0.330.0 — one Layers button on every map (with FarmOps 0.71.0 (67))**

**Migrate**: Farm Task Template gains `default_map_overlay` (Select: blank / None / Slope / Aspect). Tools: **1,153**
(unchanged; `update_farm_task_template` takes the new field).

**Why** (Tim, on FT-2026-10-00009, the Barrett Hill burn)
- "Where we have maps on the satellite / street view it may be a good idea to have the aspect and slope maps available
  there as well … and also on the server."
- "We may need to have a way of changing what layer we are looking at: satellite, aspect, street, slope."

**What changed**
- Every Desk map has a Layers button (top right): Base map, Overlay, Opacity, Show legend.
- Task / field / parcel / zone maps paint slope or aspect only inside the record's outline.
- `/app/farm-overview` and `/app/land-map` paint the whole farm (the RDO view).
- Contractor share links (`/farmops/api/job/<token>`) get the same button, slope tiles limited to the job's blocks.
- A template can name the overlay its tasks open on.

**Needs**: the slope layer built on the site (`build_slope_aspect_layer`, once). Unbuilt, the overlay rows say so.

**After deploy (the user applies over MCP; nothing is written to OML by this release)**
1. Switch on `update_farm_task_template`, then for each burn / dozer / tree-removal template:
   `update_farm_task_template template="<name>" default_map_overlay=Slope`
2. Check: open FT-2026-10-00009 in the Desk → Where the Work Is → Layers → Slope, painted inside the blocks.
3. Hard-refresh the Desk once (the switcher is a new asset: `/assets/erpnext_mcp/js/map_layers.js?v=0.330.0`).

**Deploy: v0.241.0 — crop stage: capture and timeline**

**Migrate needed**: one Crop Observation field (`stage_flags`), two switches. Two new MCP tools —
`get_stage_timeline` (read, on) and `record_growth_stage` (write, off). The phone screen follows in an app release.
**umbrel.local only.** Apply after v0.240.0.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.241.0"`), build the fafo-erpnext image.

**2. Server, over SSH to umbrel.local**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect `__version__ = "0.241.0"`.

**3. Turn it on**

ERPNext MCP Settings: tick **Record Growth Stage** (the phone's stage picker uses it too).

**4. Checks**

1. `record_growth_stage` `block: "B7"`, `bbch: "53"`: a Crop Observation of type Growth Stage, no flags.
2. Again with `bbch: "51"`: kept, flagged "Earlier than BBCH 53 … check which is right".
3. With `stage: "tight cluster"` and no code: kept, flagged "No BBCH code".
4. `get_stage_timeline` `block: "B7"`: oldest first, the flags, the current stage and its age.
5. Start a task on a block with no stage this year: the answer carries `stage_prompt` ("What stage is B7 at?").
6. `check_go_hold` on a task under a rule reading `phenology.bbch`: it now reads the recorded stage.

**5. Rollback**

Additive. Untick the switch; the observations stay as ordinary Crop Observations.

**Deploy: v0.305.0 — Washington paid sick leave, and opening balances**

**Migrate**: Farm Sick Time Ledger gains `work_state` (OR / WA). Existing rows stay blank, which reads as Oregon.
Nothing is rewritten. Tools stay at 1,142.

**What changed**
- **Washington paid sick leave** (RCW 49.46.210; WAC 296-128) is its own balance for hours worked in Washington:
  - **Accrual:** 1 hour per 40 hours, by payroll, with no annual accrual or use cap.
  - **Carryover:** up to 40 hours into the next year.
  - **Use:** from the 90th day; the balance is restored on rehire within 12 months.
  - **Pay:** paid at every employer size.
- **Policy:** these values sit in `sick_time_policy.washington`. A policy published before this release reads the
  Washington defaults. The validator refuses anything below the statute.
- **Filing and balance:** `create_leave_request leave_type="Washington Paid Sick Leave" hours=… from_date=…` files
  it; `get_leave_balance` with the same leave type reads it.
- **Pay statements:** they show the Washington balance beside Oregon's when the worker has any.
- **Opening balances:** `set_opening_balance kind=sick_time balances=[{employee, hours, work_state}]` books
  balances carried in from the old payroll as ledger Adjustment rows.
  - All rows are checked before any is written; a second opening for the same worker and state is refused.
  - Oregon openings over the 80-hour balance cap are refused.
  - An opening counts in the balance, not in the year's accrual.

**Still for the CPA**

The Washington rate for piece-rate work ("normal hourly compensation", WAC 296-128-620). This release pays at least
the hourly rate and the Washington minimum wage.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.305.0`, then `bench --site frontend migrate` and restart.

**Rollback**

Roll back to the v0.304.0 image. Washington rows stay in the ledger, but the v0.304.0 code ignores the
`work_state` column, so it would count them as Oregon. Don't run payroll on v0.304.0 after Washington rows exist.

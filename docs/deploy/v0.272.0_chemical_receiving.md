**Deploy: v0.272.0 — chemical receiving**

**Migrate needed.** It adds the doctype Supplier Delivery Intake (with its lines), the config kind Supplier Connector,
four example connectors as **drafts**, the "Chemical delivery check-in" task template and ten MCP switches (four reads
ON, six writes OFF). The phone screen comes with **FarmOps 0.56.0**. Contract:
`docs/contracts/chemical_receiving_v0_272.yaml`.

**Receiving is OFF for every company** until it is turned on per company. Nothing is received, drafted or submitted by
this release, and no stock moves until a person submits a draft receipt.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.272.0"`), build the fafo-erpnext image with `ERPNEXT_MCP_VERSION=0.272.0`.

**2. Server, over SSH to umbrel.local**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect `0.272.0`, and "supplier connectors seeded as drafts … wilbur_ellis_portal_csv, nutrien_portal_csv,
wilbur_ellis_email_pdf, agvance_rest_api".

**3. Turn it on for a live company (Tim, in the Desk; a few minutes)**

1. Desk → **Farm Feature Flag**, for that company only:
   - `chemical_receiving_enabled` (Flag) ticked;
   - `chemical_storage_warehouse` (Text) set to the shed's Warehouse, e.g. "Chemical Shed - …";
   - optionally, `receiving_qty_tolerance_pct` (Threshold), e.g. 2.
2. Products: tick **Has Batch No** on the chemical Items whose lots you want kept in stock. Attach each product's
   **SDS** to its Item, with "SDS" in the file name. Fill in the label's storage wording; "do not freeze" marks a
   product as freeze-sensitive.
3. **Supplier Connector** (Desk → Farm Config Version, kind Supplier Connector), for each supplier you use:
   1. Open the seeded draft.
   2. Set the Supplier to your Supplier's exact name.
   3. Check the CSV column names against a real portal export, or the line pattern against a real emailed invoice.
   4. Add their item numbers → your Items.
   5. Publish.

**4. Checks**

1. Upload a portal export with `ingest_supplier_csv company=… connector=wilbur_ellis_portal_csv` and pass the file.
   You get one intake per invoice, each line matched to the PO and Items, with short and over lines flagged.
2. `get_delivery_intake`: lines, matches, what is ordered but not delivered, restricted-use products, and products
   with no SDS.
3. Settle each flagged line (`resolve_delivery_line` Accept or Reject). Then `draft_delivery_receipt`. That gives:
   - a DRAFT Purchase Receipt in the shed warehouse, with batches for the lots;
   - a "Chemical delivery check-in" task on the board. Only an Applicator License holder can claim it when a
     restricted-use product is on it.
4. Check the draft against the ticket and **submit it in ERPNext**. Stock moves only then.
5. A supplier delivery job (v0.271.0): the driver's ticket photo opens an intake with the photo attached, waiting
   for lines.

**Rollback**

The v0.271.0 image. Intakes, connectors and draft receipts stay and are ignored. Draft receipts can be deleted in the
Desk.

**Deploy: v0.264.0 + FarmOps 0.50.0 — pest degree days per block, on the farm's own weather**

Apply after v0.263.0, on umbrel.local first. It needs a migrate, which does three things:

- seeds and publishes two IPM Settings, `pest_dd_models` and `pest_dd_offsets`;
- seeds two Go/Hold presets, OFF;
- adds two MCP switches: `get_pest_dd_status` (read, ON) and `calibrate_pest_dd` (write, OFF).

Deploy the server first. FarmOps 0.50.0 asks for degree days only when a block is chosen.

**Which weather is "the metro weather"**

It is **Open-Meteo**, the service Weather Settings points at. The existing degree-day and forecast tools already
use it: the archive up to 6 days ago, then the 16-day forecast, read at each block's H3 grid cell. It is a
modelled grid, not a physical station, so "station used" in every answer is the grid cell, its coordinates and
the cell elevation Open-Meteo reports.

**Before relying on a date: the models**

- The IPM reference has degree-day numbers for **4 of its 28 pests**: western cherry fruit fly, spotted wing
  drosophila, codling moth and obliquebanded leafroller.
- Its bases are written in °C, and its totals match the published °F models. v0.264.0 states the units
  explicitly and marks all four **VERIFY**.
- OBLR has no event totals.
- None of the four has an upper threshold.
- Fix them in `pest_dd_models` (list_configs → draft_config → a person publishes) against the WSU Decision Aid
  System / UC IPM models before relying on a date.
- The other 24 pests have no model until one is added.

**Block offsets**

- **Default table:** small and documented. South and south-west facing slopes run up to +1.5 °F a day, north
  facing −1 °F, scaled by slope (full effect at 15°). The total is capped at ±4 °F.
- **Elevation:** −3.5 °F per 1,000 ft against the weather cell. This needs the aspect layer rebuilt once so it
  keeps its elevation grid: run `build_slope_aspect_layer` after the migrate.
- **Calibration:** `calibrate_pest_dd` suggests a block's offset from its first trap catches, or from a supplied
  list. Tim's historical harvest dates by block can feed it once a cherry phenology model exists in
  `pest_dd_models`.
- Calibration only ever writes a **Draft**. A person publishes it in the Desk.

**1. Build (Tim)**

1. Push erpnext_mcp main (`__version__ = "0.264.0"`) and build the image.
2. Archive FarmOps **0.50.0 (build 45)**, scheme FarmOps.

**2. Server (umbrel.local)**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate
sudo docker restart fafo-erpnext_server_1
```

Expect `IPM setting FCV-… seeded.` twice.

**3. Checks**

1. Run `build_slope_aspect_layer` once, so blocks get their elevation.
2. Run `get_pest_dd_status` for a cherry block. Each of the four pests shows:
   - degree days since its biofix;
   - the next event, e.g. "~Jun 3 ±2 d (forecast)";
   - the block's offset with its reasons;
   - the source (Open-Meteo), the grid cell and the citation;
   - the "verify" caveat.
3. The phone (0.50.0), with a block picked on the IPM map:
   - pest nodes show their next-event date;
   - the node sheet has a "Degree days on this block" section;
   - "Degree days" lists all four.
4. The Desk IPM Map, with a block picked: pest labels show the next date, and the side panel shows the degree
   days and the offset.
5. `get_map_overlays` with `layers: pest_dd` (as Foreman or Farm Manager) gives each block its pest windows.
   Without `layers`, the answer is unchanged.
6. Go/Hold presets `go_hold_spray_fruit_fly_window` and `go_hold_spray_swd_window` exist and are disabled.

**4. Rollback**

The v0.263.0 image. The IPM Settings stay as Farm Config Version rows; older code ignores them.

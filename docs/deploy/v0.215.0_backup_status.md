# Deploy: backup status (server v0.215.0; no app change)

Contract: `docs/design/backup_status.md`. Rides on v0.211.0–v0.214.0.

## 1. Server

1. Push `erpnext_mcp` `main`; build the image at the commit that carries `__version__ = "0.215.0"`.
2. `bench --site <site> migrate`. Expect: Backup Record gains two hidden columns, `ingest_key` and
   `test_ingest_key`. Nothing else; no record is written by the migrate.
3. Nothing to switch on: `get_backup_status` is a read tool (on by default) and the ingest is on the
   hourly scheduler.

## 2. What it needs from the boxes

The erp-backup kit (2026-10-01.2) already writes `<bench>/sites/erp_backup_status/<box>.json` inside
the ERPNext container. **No API token goes on either box** — the app reads the file.

## 3. Settings (Farm Feature Flags, all optional)

| Flag | When | Default |
|---|---|---|
| `backup_record_company` | Which company the Backup Records are filed under | the site's default company |
| `backup_box` | Only if more than one status file is in the directory: which box this site is (`oml`, `umbrellocal`) | the one file present |
| `backup_peer_is_offsite` | Set true once the peer is at a different physical site; the copy is then recorded as an Offsite Replica | false |

## 4. What to check after

```
get_backup_status
```

- `overall: ok` and no alerts on a healthy pair. `NO_STATUS_FILE` means the kit's copy into the
  container is not there; `REPORTER_DEAD` means the file is over 26 h old — check the timers.
- Within the hour (or run `erpnext_mcp.backup_status.ingest` as a System Manager from the Desk
  console): `list_backup_records` shows a Full record for last night's set, a second for the copy on
  the peer, and — once the peer has restored it — a Pass on that copy with "By erp-backup@<peer>".
- Run the ingest twice: no new rows.

## 5. Differences from the spec, for Tim

1. `test_restore_by` is a Link to User, so `erp-backup@<box>` is the first line of the test notes
   and the field is left empty.
2. The idempotency key is a hidden column, not text in the notes.
3. With two status files and no `backup_box` flag, the ingest does nothing and says so; the read
   tool still reports both.

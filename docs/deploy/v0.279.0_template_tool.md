**Deploy: v0.279.0 — one template tool (consolidation phase 1)**

**No migrate.** One new MCP switch, `allow_template`, off by default. Tools go from 1,136 to 1,137: one is added,
and nothing is removed or hidden.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.279.0"`), build the fafo-erpnext image with `ERPNEXT_MCP_VERSION=0.279.0`.

**2. Server**

```zsh
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect `0.279.0`.

**3. Turning it on (Tim)**

1. ERPNext MCP Settings: tick **Template (every kind)** (`allow_template`). Reads work at once (kinds, describe,
   list, get, preview, history, diff).
2. A write through `template` also needs that kind's own switch, the same one the old tool uses. For example,
   creating a farm task template needs `allow_create_farm_task_template`, and drafting a config kind needs
   `allow_draft_config`. Nothing new is opened.
3. Reconnect the MCP client so it sees the new tool. Start with `template action=kinds`, then
   `template action=describe kind=…`.

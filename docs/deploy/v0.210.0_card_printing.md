# Deploy: card printing from ERPNext Desk (v0.209.0 → v0.210.0)

The server draws the CR80 card Tim chose; the Employee and Asset Register forms download it;
a person prints it and marks the job. There is **no print agent** — do not install
`cardprint_agent/`. Contract: `docs/design/card_print_queue.md` (Amendments 1–4). The phone
(gated screens) is a separate, later deploy; nothing here needs it.

## 1. Ship it

1. Push `erpnext_mcp` `main`.
2. Build the image at the commit that carries `__version__ = "0.210.0"`. No new Python
   packages: it uses reportlab and segno (already in the image); pypdf only in tests.
3. `bench --site <site> migrate`. It prints one line listing what it created. Expect:
   - fields `Employee.badge_title`, `Employee.badge_category`, `Employment Type.badge_category`;
   - a first Badge Category on each Employment Type that had none
     (`Operator → Owner / Operator`, `Full-time → Employee`, …);
   - print formats `Employee ID Card (CR80)` and `Asset Tag Card (CR80)`, set as the default
     for Employee / Asset Register where no default was set;
   - the `Employee — Print ID Card` and `Asset Register — Print Asset Tag` buttons (revision 3);
   - patches `card_backs_landscape_cw` (the back is a landscape page, rotated clockwise) and
     `card_stations_printed_by_hand` (the print station becomes Manual).
4. **Roles — this is the gate.** Only **Card Print Requester**, **Farm Manager** and
   **System Manager** can ask for a card, see the queue or close a job; the server refuses
   everyone else, on Desk, on the phone and over MCP. Give Card Print Requester to anyone
   else who should print. A requester only reaches their own company's employees and assets
   (their Company User Permissions; on the phone, their enrolled entities).
5. ERPNext MCP Settings — tick the tools the post-deploy steps use:
   `allow_attach_file_to_document`, `allow_update_company`, `allow_update_employee`,
   `allow_download_card_pdf`, `allow_mark_card_print_job`. (The Desk buttons need none.)

## 2. Post-deploy, over MCP

Run against the site being set up. Each step is one tool call. The MCP account needs one
of the three roles in §1.4.

**a. The logo.** The file is `~/Documents/Misc/OrchardMeadowLogo.png` (406 px wide — it
prints, and the dialog will say it is under the 600 px a clean print wants; replace it with
a larger one when there is one).

```
attach_file_to_document
  doctype: "Company"   name: "<the company docname>"
  file_name: "OrchardMeadowLogo.png"
  file_content: <base64 of the file>      # base64 -i ~/Documents/Misc/OrchardMeadowLogo.png
  is_private: false
→ returns file_url, e.g. "/files/OrchardMeadowLogo.png"

update_company
  company: "<the company docname>"
  badge_logo: "<that file_url>"
```

Or in Desk: Company › Badge Logo › Attach.

**b. Tim's card.** Designation stays `Operator`. The bar comes from Employment Type
`Operator` (→ OWNER / OPERATOR); only the title is set.

```
update_employee
  employee: "<Tim's Employee docname>"
  badge_title: "Manager"
```

If his Employment Type is not `Operator`, either set it (`employment_type: "Operator"`) or
set the bar directly (`badge_category: "Owner / Operator"`).

**c. Test-render both cards.** Each call draws the card, stores the PDF as a private File,
and records a `Downloaded` Card Print Job.

```
download_card_pdf   job_type: "Employee ID"   reference_name: "<Tim's Employee docname>"
download_card_pdf   job_type: "Asset Tag"     reference_name: "40-WM-SE"
→ each returns file_url, bytes, warnings, and job.name
```

Open the `file_url` in a browser signed in to the site, or read it back with
`list_attachments` (doctype `Card Print Job`, the returned `job.name`) then
`get_attachment_content`.

What to check: two pages, **both 85.6 × 54 mm landscape**; page 2 is the back turned 90°
clockwise. Employee: "Manager" under the name, the green bar reading `OWNER /` over
`OPERATOR`, badge `OML-0001`. `warnings` should be empty apart from the logo-size note
(and the no-photo note until a photo is on the Employee record).

**d. Close the test jobs** once the cards are printed (or not):

```
mark_card_print_job   name: "<job.name>"                  # it printed
mark_card_print_job   name: "<job.name>"  printed: false  error: "test render only"
```

Once a card is marked **Printed**, the next request or download for it needs a
`reprint_reason` (Lost / Damaged / Details changed / Other: …). A job left Downloaded or
marked Failed does not count as printed.

## 3. Printing a card (the whole flow, in Desk)

1. Employee or Asset Register form › **Card** › **Print ID Card** / **Print Asset Tag**.
   The dialog shows both sides and any warnings.
2. **Download card PDF.** The PDF opens; a Card Print Job is recorded as Downloaded.
3. Print from Preview: Paper Size **CR80 / ISO 7810**, Scale **100 %**, Scale to Fit **off**,
   Auto Rotate **off**. Print page 1, flip the card, print page 2.
4. Back in ERPNext, the *Did it print?* box: **Mark printed**, or **Mark failed** and say why.
   Closing the box leaves the job Downloaded; finish it later from the Card Print Job list.

**Add to print queue** (the dialog's second button, and what the phone does) files the card
as Queued instead. Whoever is at the printer opens **Card Print Job** (filter Status =
Queued), opens a row, **Open card PDF**, prints it, and **Mark printed** / **Mark failed**.
A Failed job can be **Retried** (back to Queued) or marked printed after a reprint.

## 4. If something is off

- **"…may not print cards or see the print queue"** — the account lacks the role (§1.4).
- **"no Employee called …" for someone who exists** — they belong to a company outside the
  caller's; that is the company scope, worded like a missing record on purpose.
- **The bar is blank** — the Employee has no Badge Category and their Employment Type has
  none (or they have no Employment Type). Set either one. It is never defaulted to EMPLOYEE.
- **The back comes out turned the wrong way** — Card Print Station › Back Orientation:
  `Landscape, rotated CCW`, or `Portrait` for a 54 × 85.6 mm page.
- **Print from the form's printer icon gives A4** — the doctype already had a default print
  format, so the CR80 one was not forced over it. Pick `Employee ID Card (CR80)` in the print
  view, or use the Card button, which never goes through the print dialog.
- **"10 print requests in a minute"** — the rate limit (10 a minute, 100 a day per account).

Nothing in this deploy writes to a site by itself beyond the migrate items in §1.

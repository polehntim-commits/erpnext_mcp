# Deploy: v0.225.0 — secure direct-deposit setup (app 0.32.0)

Code plus one migrate (Employee Bank Account fields and statuses, Signing Evidence methods, settings, a
daily job). Everything is off; nothing changes until ticked.

1. Build at `__version__ = "0.225.0"`; `bench migrate`; restart workers. Ship app 0.32.0.
2. **Decide (design §6)**: Plaid use case (recommended: a separate Auth + Identity use case on the same
   Plaid team), the hold (14 days), the name rule, and accepting photos as "needs review".
3. **Without Plaid** (works today, including Cash App): tick **Workers change direct deposit in the
   app**. A worker: My records → Direct deposit → Change account → (Face ID) → Upload your bank's form
   (Cash App: Money → Direct deposit → the form PDF). HR: Employee Bank Account (status Pending) →
   check → **Approve**. Then the next `generate_prenote_file` (open the Payroll window) includes it; it
   is paid from the date shown ("Paid from"), and the old account stops then. If the bank returns the
   prenote: **Prenote returned** on the form.
4. **With Plaid**: ERPNext MCP Settings → Plaid client id, secret, environment (sandbox first) → tick
   **Verify with Plaid**. Test with Plaid's sandbox institution on umbrel.local before production.
   Untested against Plaid itself in this release (the suite uses a fake transport).
5. Every step sends the worker a notice (email on file + push) with no numbers; the full account number
   is only in the encrypted field and the NACHA/prenote files.

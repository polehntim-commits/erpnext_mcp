**Deploy: v0.322.0 — every Housing Unit has its Asset Register tag (fixes Tim's missing Mill Creek cabins)**

**Migrate** (Housing Unit gains `asset_tag`; a patch backfills the tags). Tools: **1,150 → 1,150**. No phone release
needed.

**The bug**

Tim registered MC-CABIN-1&2 and MC-CABIN-3&4 from the phone on 2026-10-11:
- the calls were `mobile:create_housing_unit`, FarmOps build 56, at 16:26 and 16:29;
- the MCP Action Log confirms it.

They never appeared on the phone's map or asset lists. The reason:
- Those read the **Asset Register**, the one register for anything with a tag, a QR and a place on the map.
- `create_housing_unit` wrote only the Housing Unit, on every path (phone, MCP and Desk).
- `related_asset` (null on both) is a different link: the fixed-asset `Asset` for depreciation. It was not the
  cause.

**The fix (the Repeatable Asset Pattern: one register for anything scannable)**
- **Saving a Housing Unit** (Desk form, `create_housing_unit` over MCP, or the phone) now pairs it with one Asset
  Register row:
  - type **Housing Unit**, the parcel's company and the unit's GPS;
  - the unit's docname as the printable tag ID, so the QR comes with it;
  - the parcel in the description;
  - the link is on the unit as `asset_tag` (read-only), and `get_housing_unit` / `list_housing_units` return it.
- **Each later save keeps the tag in step:** company, GPS, and the description while it is still the generated one.
- **No duplicates:** an Asset Register row already carrying the unit's name and a building type is adopted, not
  duplicated. A non-building row with that name is left alone, and the tag is named "<unit> (housing)".
- **Never blocks a save:** a failure is logged and retried on the next save.
- **Deleting a unit retires its tag**, so its scan and task history are kept.
- **The Desk Farm Overview draws a cabin once.** It already draws Housing Units as their own layer, so their tags
  are left off its asset layer.
- **Patch `housing_unit_asset_tags`** pairs every existing unit. It is idempotent: a second run creates nothing.

**Other registers checked (item 4):**
- Fields and parcels are drawn from their own read (`get_field_map`).
- Irrigation zones come from the location registry.
- Valves, structures, hazard pins, wells and tanks already live on the Asset Register.
- Only Housing Units had the gap.

**After deploy (OML, then umbrel.local)**

1. The migrate prints `MC-CABIN-1&2 - MC → MC-CABIN-1&2 - MC, MC-CABIN-3&4 - MC → …`.
2. `list_assets asset_type="Housing Unit"` returns both, with GPS.
3. On the phone, pull to refresh Today / Ground: both cabins are pinned at Mill Creek. Print their QR from the
   asset (`generate_asset_qr`) if Tim wants stickers. Printing is Tim's call.
4. `run_post_deploy_check expected_version=0.322.0`.

# Deploy: v0.226.0 — offline Add Asset (app 0.33.0)

Code plus one migrate (new columns on Asset Register, Housing Unit and Card Print Job; two tool
switches). Nothing changes until a phone running 0.33.0 sends `tag_uuid` / `request_id` — every other
caller gets the old behaviour. Tag printing stays **off** unless a person ticks "Print a tag".

**Test on umbrel.local only.** Not OML until Tim says so.

1. Build at `__version__ = "0.226.0"`; `bench migrate`; restart workers. Ship app 0.33.0.
2. Check the migrate: Asset Register and Housing Unit have a collapsed **Made on a phone** section
   (Tag UUID — unique, Request ID, Created offline, Saved on phone at, Phone, Needs review, Review note);
   Card Print Job has **Tag format** and **Location**.
3. On the phone, before Mill Creek: Settings → **Prepare for offline** (downloads types, the register,
   parcels, housing units, employees; shows "Last synced").
4. Airplane mode → Add asset (a pump; a Cabin with beds) → photos → Save → **Add another** (keeps
   place/type, numbers the name). Force-quit, reopen: the drafts and "On this phone — N waiting" are
   there; the QR shows on screen and shares as an image.
5. Back online → **Sync now** (or wait for the connection). Badges go Syncing → Synced. In the Desk the
   record shows Created offline with the phone time; its comment says so.
6. Scan the on-screen QR: it opens the record (UUID resolves, before and after sync).
7. Duplicates: register one with a serial number already on the register → **Needs attention: possible
   duplicate** → Keep as new, or It's the same one (the tag is added to that record's Tag aliases).
8. Printing (optional): tick **Print a tag** with a format. Desk → Card Print Job list → **Print tags for
   a location** → Card jobs stay with the card printer; Outdoor label / Sheet jobs open one QR sheet
   (print at 100 %) and are marked Printed; a second copy needs a reprint reason.

**Settings**: `allow_list_tag_print_queue` (read, on), `allow_print_tags_for_location` (write, off) —
MCP only; the phone and Desk use the Card Print Requester role as before.

**New routes**: `/files/get_staged_upload`, `/mobile/list_tag_print_queue`,
`/mobile/print_tags_for_location` (183 mobile methods). `register_asset` and `create_housing_unit`
take `tag_uuid`, `request_id`, `device_created_at`, `offline`, `created_device`, `review_note`,
`confirm_new`, `link_to_existing` (and the housing route now takes `gps_latitude`/`gps_longitude`).

**Rollback**: the columns are additive; an older build ignores them. A phone on 0.33.0 talking to an
older server has the new arguments dropped by the sidecar: creates still work, but a resend is not
recognised (a lost reply comes back as "already has a record"). Upgrade the server before Mill Creek.

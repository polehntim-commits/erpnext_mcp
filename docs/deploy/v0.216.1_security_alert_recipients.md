# Deploy: v0.216.1 — Security Alert Recipients; PDFs inside the container (no app change)

Patch on v0.216.0. Code plus one migrate. Contracts: `docs/design/farmops_only_funnel.md` (H4) and
`docs/design/pdf_base_and_mail.md`.

## Steps

1. Build the image at the commit with `__version__ = "0.216.1"`; `bench --site <site> migrate`.
   Expect:
   - ERPNext MCP Settings: **Security Alert Recipients** (empty), **PDF Asset Base URL** (empty),
     and the switch **Test PDF Rendering** (on);
   - patch `zoho_accounts_send_as_account` prints which Email Accounts it ticked
     "Always use this email address as sender" on (Zoho accounts only; none otherwise).
2. Restart **all** workers (web, the queue workers, and the sidecar): the PDF fix is installed
   per process, and a queue worker older than the deploy still sends with the old behaviour.
3. Optional: fill in Security Alert Recipients (comma/semicolon list). Empty = the System Managers.
4. Leave PDF Asset Base URL empty (it detects `http://127.0.0.1:8080`). Type `off` to go back to
   Frappe's own behaviour if a PDF ever looks worse than before.

## Check

- `get_server_status` → `erpnext_mcp_version: 0.216.1`; `pdf.base_url: http://127.0.0.1:8080`,
  `pdf.source: auto`; `email.warnings` empty (or read them).
- `test_pdf_rendering` → `ok: true`, `pdf_base.assets.status: 200`.
- `test_pdf_rendering` with `doctype: Employee`, `name: <an employee>` → the real print renders.
- Desk: Employee list → select two → Print → PDF: not blank.
- Email Queue: retry one of the rows that failed with HostNotFoundError (Email Queue → the row →
  "Retry sending") — it sends with the PDF attached.

## What it does not change

`host_name`, password-reset / two-factor / "view online" links, email bodies, the weekly drift
report, the phones, the Funnel.

**Deploy: v0.325.0 — file links both ways (large files as plain HTTP, not base64 through MCP)**

**Migrate**:
- Upload Link gains `direction`, `preset_file_name`, `expected_size` and `company_guard`;
- ERPNext MCP Settings gains `file_link_host` and `allow_get_attachment_download_link`.

Tools: **1,152 → 1,153**. No phone release; Funnel untouched.

**What changed** (Tim, 2026-10-13)
- **DOWNLOAD — `get_attachment_download_link file=<File>`** (new, default OFF):
  - one File, single use, `expires_minutes` default 10 (1–1440);
  - your read permission on the document the file hangs on is checked when the link is issued;
  - the response streams the file at any size with `Content-Disposition: attachment`, then the link is 404;
  - logged in the MCP Action Log as `file_link:issued` / `used` / `expired` / `revoked`, as well as on the link's
    own row;
  - revoke with `revoke_upload_link upload_id=DNL-…`;
  - `share_link kind=download` reaches the same tool.
- **UPLOAD — the existing `request_upload_url` (v0.244.0), extended rather than duplicated:**
  - **New arguments, checked at issue before anything is sent:** `file_name` names the File (its extension must
    suit the link, and a file of that name already on the document is refused), `expected_size` must match exactly,
    and `company` applies the company guard from attach_file_to_document.
  - **Unchanged:** the declared sha256, private by default, the parent-write and cancelled-parent checks, the
    single use, and the reply carrying the File and its sha256.
  - **Default TTL is now 10 minutes** (was 15).
- **One table, one engine:**
  - `list_upload_links` gets a `direction` filter (Upload / Download);
  - tokens stay 32 random bytes, stored only as their SHA-256;
  - any bad token is the same 404 "Not found.";
  - every route is metered per address before the token is read.
- **Where links point: ERPNext MCP Settings → File Links: Host.**
  - **Desk (default):** `https://<the Desk host>/api/method/erpnext_mcp.file_links.download?token=…` (and
    `.upload?token=…`), served by ERPNext itself. On this farm that host is reached over Tailscale; the public Funnel
    publishes only /farmops, so these links are not public.
  - **Public (Funnel):** the sidecar's `/farmops/api/download/<token>` and `/farmops/api/upload/<token>`. Choose
    this only on purpose.
  - While the host is Desk, the public routes refuse every token, including the existing upload route.
- **Size:**
  - downloads stream at any size;
  - uploads through the Desk host stop at the ERPNext proxy's `CLIENT_MAX_BODY_SIZE` (50m in
    fafo-erpnext's supervisord.conf), so a larger PDF needs that raised by Tim or the Public host (100 MB ceiling);
  - uploads keep each link's own `max_bytes` (default 25 MB) below those.

**Use**

- **Download a large file to a Mac folder:**
  1. `get_attachment_download_link file=<File docname>` (find it with `list_attachments`).
  2. `curl -fOJ '<url>'` in the folder, or open the URL in Chrome.
- **Upload a large PDF without chunking:**
  1. `request_upload_url doctype=… name=… file_name="Operating Agreement.pdf" expected_size=<bytes> sha256=<hex>`.
  2. `curl -fT "Operating Agreement.pdf" -H 'Content-Type: application/pdf' '<url>'`.
  3. The answer carries the File docname and sha256.

**After deploy (Tim)**

1. ERPNext MCP Settings: Upload Links Enabled (already, if upload links were in use), tick Get Attachment Download
   Link, and leave File Links: Host on Desk.
2. From a Mac on the tailnet: issue a link for a small PDF, `curl -fOJ` it, and run it again: the second answer is
   404.
3. `run_post_deploy_check expected_version=0.325.0`.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.325.0`, then `bench --site frontend migrate` and restart.

**Rollback**

Roll back to the v0.324.0 image. Download links stop resolving; upload links fall back to the v0.244.0 behaviour.

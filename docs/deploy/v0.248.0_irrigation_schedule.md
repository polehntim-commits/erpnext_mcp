**Deploy: v0.248.0 — the irrigation schedule**

**Migrate needed**: a Schedule table on Irrigation Zone (new child doctype Irrigation Schedule Line), task type
Irrigation on Farm Task and Farm Task Template, three settings fields, a sixth Work Timing preset seeded OFF. Two new
MCP tools — `get_irrigation_schedule` (read, on), `set_irrigation_schedule` (write, off). New 00:15 job.
**umbrel.local only.** Apply after v0.247.0.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.248.0"`), build the fafo-erpnext image.

**2. Server, over SSH to umbrel.local**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect `__version__ = "0.248.0"`.

**3. Set a schedule**

1. Desk → an Irrigation Zone → Schedule: add a set — Valve (the zone's valve), Days `Mon Wed Fri`, Start 06:00,
   Minutes 120. (Or `set_irrigation_schedule` with **Set Irrigation Schedule** ticked.)
2. ERPNext MCP Settings: tick **Irrigation Schedule** to raise each day's sets as tasks.

**4. Checks**

1. The next morning after 00:15: an Irrigation task "Irrigate Zone … — <valve>, 06:00, 120 min" on the zone's block,
   valve as its asset; only one per set and day.
2. Open and close the valve as usual. `get_irrigation_schedule` for the zone and this week: that day reads done (or
   short / missed), with planned and ran minutes; a run with nothing planned reads extra.
3. Optional: approve the preset **Irrigation: rain forecast**; with ¼ in or more forecast, `check_go_hold` on the task
   reads Hold with the reason.

**5. Rollback**

Untick **Irrigation Schedule**; no tasks are raised. The schedule stays on the zone.

**Deploy: v0.303.0 — the crop stage table as config**

**No migrate.** A site that already has `crop_phenology@1` keeps it. The new keys are read with defaults: no stages,
and the site biofix. Tools stay at 1,142.

**What changed**
- **Stages as config:** each crop's degree-day stage table (`stages: [[BBCH, °F·days], …]`) and an optional
  `biofix` now live in the `crop_phenology` IPM setting beside its base. They're drafted, previewed and published
  by a person, as the plan intended, instead of being a Settings text box.
- **Fallback:** the Settings Degree-Day Stage Table still works for a crop whose row has no stages.
- **Reporting:** `get_degree_days` reports `stages_source`.
- **Cherry stays empty:** sweet cherry ships with no stage rows. The proposal
  (`docs/design/cherry_dd_stage_table_proposal.md`, now on the 40.1 °F base) calibrates them from spring-2027
  observations.

**Still Tim's**

The cherry biofix: the site default, or March 1 as the proposal recommends. Set it with `config action=draft
kind=crop_phenology`, setting `biofix: "03-01"` on the sweet-cherry row, then preview and publish in the Desk.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.303.0`, then `bench --site frontend migrate` (nothing new to seed) and
restart.

**Rollback**

Roll back to the v0.302.0 image. Config stage rows are then ignored and the Settings table applies.

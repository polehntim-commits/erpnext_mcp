# Emailed links (password reset, 2FA QR, notifications) — the one-time fix, and v0.223.3

**Cause (OML, 2026-10-03).** The site config has no `host_name`, so Frappe's `get_url()` uses the
request's host — and behind the fafo-erpnext image's nginx that is the site name. Reset emails linked
to `http://frontend/update-password?key=…`. (Frappe 15's reset email calls
`get_url(…, allow_header_override=False)`, which ignores the request host on purpose and falls back to
`http://<site name>` — so `host_name` is the only fix; no proxy header can help.) After the cutover the Desk is only at
`https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443` (tailnet) and `http://100.69.162.122:5300` (LAN).

**What it does not touch.** PDFs fetch assets from `pdf_base`'s internal base (`127.0.0.1:8080`), which
ignores `host_name`; phones use Farm Ops Public URL; the MCP connection panel uses Public URL. Emailed
links will open only on a device on the tailnet — the people who use the Desk.

## 1. The fix — now, on OML (no deploy needed)

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend set-config host_name https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443
```

Verify:

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend execute frappe.utils.get_url
sudo docker exec fafo-erpnext_server_1 grep host_name /home/frappe/frappe-bench/sites/frontend/site_config.json
```

Expect `https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443` from the first and
`"host_name": "https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443"` from the second. Then, from a
tailnet browser, request a reset at `https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443/login#forgot`:
the email's link must start `https://orchardmeadow-umbrel.tail2b0bb0.ts.net:8443/update-password?key=`
and open the reset form. Frappe reads site_config.json per request, so no restart is needed; only if
the new email still says `http://frontend`, run `sudo docker restart fafo-erpnext_server_1` (about a
minute of downtime) and request again. Also check a PDF still renders: `test_pdf_rendering`.

## 2. umbrel.local (test box)

umbrel.local has no `:8443` serve; its Desk answers at `http://umbrel.tail2b0bb0.ts.net:5300` (tailnet)
and `http://umbrel.local:5300` (LAN). Over SSH to umbrel.local:

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend set-config host_name http://umbrel.tail2b0bb0.ts.net:5300
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend execute frappe.utils.get_url
```

## 3. v0.223.3 — the check

Code only; no migrate. Build at `__version__ = "0.223.3"`; restart workers.

- `get_server_status.email_links`: `host_name`, the site name, what a reset link starts with, Public URL,
  `ok`, `problems`, `warnings`, and the exact `fix` command.
- `get_security_status.emailed_links`: **fail** when `host_name` is unset, the site name or loopback;
  **warn** when it is the Funnel origin (serves only /farmops after the cutover), a bare IP with no port
  (on an Umbrel that is the dashboard), or differs from Public URL; **pass** otherwise.

# Deploy: badge photo; fixed assets (server v0.214.0, app 0.26.0)

Contract: `docs/design/badge_photo_and_fixed_assets.md`. Rides on v0.211.0–v0.213.0; deploying
0.214.0 delivers all four.

## 1. Server

1. Push `erpnext_mcp` `main`; build the image at the commit that carries
   `__version__ = "0.214.0"`. No new Python packages (Pillow ships with Frappe).
2. `bench --site <site> migrate`. Expect:
   - Farm Asset Type: `fixed_location`. Patch `flag_fixed_asset_types` prints the types it
     flagged — wind machines, water sources, valves, zones, tanks, storage, blocks, housing.
   - Asset Register: `last_scan_latitude`, `last_scan_longitude`.
     Asset State Log: `from_latitude`, `from_longitude`, `distance_m`, `client_request_id`.
   - Farm Task Template **Badge photo** seeded; button **Employee — Request Badge Photo** seeded.
   - **No asset is moved and no photo is changed by the migrate.**
3. ERPNext MCP Settings, to use them over MCP (all default OFF): `allow_move_asset`,
   `allow_undo_asset_move`, `allow_request_badge_photo`, `allow_set_employee_photo`.

## 2. App

Push `fafo_ios` `main`; build **0.26.0**.

## 3. What changes for people the moment the server is up

- **Scanning a wind machine, well, valve, tank, block or building no longer moves its pin**, on
  any app version — an older app's "Update location" on a fixed asset now does nothing to the
  position (the scan is still recorded). Moving one needs app 0.26.0, or over MCP:

  ```
  move_asset  asset_name: "40-WM-SE"  gps_latitude: 45.58125  gps_longitude: -121.1849598
              reason: "Put back after an accidental move"
  undo_asset_move  asset_name: "40-WM-SE"        (within 24 hours)
  list_asset_state_history  asset_name: "40-WM-SE"
  ```
- A type that should or should not move: Desk → Farm Asset Type → **Fixed Location**, or
  `update_asset_type name: "Fuel Tank" fixed_location: false`.
- **A card requested for someone with no photo raises a Badge photo task** for them (the card
  still queues). Turn that off with `set_feature_flag key: "badge_photo_auto_request" value: false`.

## 4. What to check after

- Scan a wind machine's tag from somewhere else: the pin stays; the asset's Last Scan
  Latitude/Longitude show where you were.
- A foreman: asset screen → hold **Move asset** → place it → "Move N m?" → reason → confirm.
  The asset's history shows Moved with from/to. **Undo move** puts it back.
- A picker sees no Move.
- Phone → My Records → **Badge photo** → front camera with a frame → consent → Complete.
  The Employee record shows the photo (private file, 600 × 750); the next ID card carries it.
- Desk → Employee → Badge › **Request badge photo** raises the task on their phone.

## 5. Decisions made here that Tim may want to reverse

1. A fixed asset with no position is not placed by a scan either — only by Move.
2. Fuel Tank and Gas Tank are fixed.
3. The server crops a badge photo about its centre when the phone did not frame it.
4. A photo is auto-requested when a card is asked for with none on file (the card still prints).

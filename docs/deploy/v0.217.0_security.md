# Deploy: v0.217.0 — security status, alerts, client IP, time-boxed switches (no app change)

Rides on v0.216.1. Code plus one migrate. Contract: `docs/design/security_status_and_alerts.md`.
**Nothing new is switched on by deploying it** beyond two read tools and a read-only alert job.

1. Build at `__version__ = "0.217.0"`; `bench --site <site> migrate`. Expect two settings on
   ERPNext MCP Settings (Trusted Proxy Ranges, empty; a hidden time-limited-switches field), two read
   switches (on), and an "Enable a tool for N minutes" button on the form.
2. Restart all workers (the scheduler picks up two 5-minute jobs).
3. Run `get_security_status` (and once with `probe_public: true` after the cutover). Read the fails
   first; each has its fix. Expect `mcp_system_user` to fail on OML until a dedicated user is set.
4. Run `list_mcp_switches` with `enabled: true` — `dangerous_enabled` should be what you meant.
5. Alerts: log in once as Administrator (or wait for the next settings change) — within 5 minutes an
   email reaches Security Alert Recipients (or the System Managers).

**Trusted Proxy Ranges — only when ready (decision for Tim):** first add `100.64.0.0/10` to Allowed
CIDRs, then set Trusted Proxy Ranges to `127.0.0.0/8` and `172.16.0.0/12`, then run
`get_security_status` and read `client_ip`: it should name a tailnet address, and the MCP should
still answer. Undo: clear Trusted Proxy Ranges.

**Time-boxed switch:** ERPNext MCP Settings → Enable a tool for N minutes → tool name, minutes. It
goes off by itself within 5 minutes of the time; an alert goes out both times.

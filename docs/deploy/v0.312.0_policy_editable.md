**Deploy: v0.312.0 — three compliance values Tim changes without a release**

**No migrate.** Tools stay at 1,142.

Each value below is a payroll setting in the config lifecycle:
- **Draft:** over MCP an AI may draft (`config action=draft kind=…`), or a person drafts in the Desk.
- **Preview:** `config action=preview` reruns a recent pay period live and staged, per employee.
- **Publish:** ONLY by a person in the Desk; MCP publish is refused.
- **Audit:** every version is kept (Farm Config Version: who drafted, who published, when, notes), and `config
  action=diff` / `rollback` work on it.

The running code reads whatever version is in force on the day.

**(a) OR-W-4 e-signature acceptance and forwarding** — `oregon_withholding`
- `esignature.confirmed`: false today ("awaiting DOR written confirmation"). Set it true with `esignature.note`
  saying how the DOR confirmed it; the validator requires the note. `require_verified_signer` cannot be turned off.
- `forwarding.days` (20, allowed 1–60) and `forwarding.basis`: `signature` (the default — 20 days from the employee's
  signature, Tim's reading) or `received` (from the day the employer received it). New in this release, since the
  basis was hard-coded.
- A version drafted before these keys existed still validates; the seed's values apply.

**(b) Oregon bonuses in the regular rate** — `pay_item_policy`

`states.OR.bonuses_in_regular_rate`: true by default. Setting it false needs an attorney's advice, and the validator
warns. Washington's cannot be turned off.

**(c) Garnishment order and limit tables** — `garnishment_policy` and `garnishment_limits`
- `priority`: the stacking order. The validator keeps child support first (42 U.S.C. 666(b)(7)).
- The limit tables are dated rows: federal; Oregon floors and support floors; Washington floors, consumer,
  spousal-maintenance and private-student-loan rules.
  - A new row with a later `effective_from` takes over on that day, e.g. Oregon's July 1 update.
  - The validator now checks the v0.311.0 sections' shapes.

**Build / server**

Push and build with `ERPNEXT_MCP_VERSION=0.312.0`, then `bench --site frontend migrate` (nothing new) and restart.

**Rollback**

Roll back to the v0.311.0 image. The forwarding basis goes back to fixed-at-signature, which is the same as the
default.

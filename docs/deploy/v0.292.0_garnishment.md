**Deploy: v0.292.0 — garnishment catch-up (the middle path) and pay items**

**Migrate.** New doctypes: Farm Pay Item, and Farm Payroll Deduction Ledger (a child table on Farm Payroll
Deduction). Farm Payroll Deduction gains `arrears_opening`, `arrears_per_period`, `consumer_debt`, `arrears_balance`
and the `ledger`. The migrate seeds payroll settings `garnishment_policy` and `garnishment_limits`, the dated and
sourced federal, Oregon and Washington limits.

Tools stay at 1,142. Some existing tools gain arguments: `create_payroll_deduction` / `update_payroll_deduction` /
`create_garnishment` / `update_garnishment` take `arrears_opening`, `arrears_per_period` and `consumer_debt`, and
`list_employee_deductions` takes `work_state`. No payroll has run through this app on either server.

> **Payroll / CPA review before live use.** Have payroll or the CPA review these before the first live run with a
> garnishment or a pay item:
> - the catch-up policy;
> - the limit tables;
> - the order of priority;
> - how each pay-item kind is taxed. "Not subject to withholding" is for a fishing-boat crew share under IRC
>   3121(b)(20). Whether a bonus changes the FLSA regular rate is not computed.

**1. Build (Tim)**

Push erpnext_mcp main (`__version__ = "0.292.0"`), then build the fafo-erpnext image with
`ERPNEXT_MCP_VERSION=0.292.0`.

**2. Server**

```zsh
sudo docker exec -u frappe -w /home/frappe/frappe-bench fafo-erpnext_server_1 bench --site frontend migrate
sudo docker restart fafo-erpnext_server_1
sudo docker exec fafo-erpnext_server_1 grep __version__ /home/frappe/frappe-bench/apps/erpnext_mcp/erpnext_mcp/__init__.py
```

Expect:
- the version to read `0.292.0`;
- the migrate to print `payroll setting payroll_setting:garnishment_policy@1 seeded.` and the same line for
  `garnishment_limits`.

**3. Checks**

1. `config action=get kind=garnishment_limits`. Expect a federal row (7.25, 25%, support 50/55/60/65, student loans
   15%), Oregon rows dated 2025-01-01, 2025-07-01 and 2026-07-01 (weekly floor 400 from 2026-07-01), and Washington
   2026-01-01. Each row should carry a source.
2. `config action=get kind=garnishment_policy`. Expect `catch_up: middle_path` and the priority support → tax levy
   → student loan → creditor, with `priority_source`.
3. `list_employee_deductions` with `gross_pay` for someone who has an order. The preview shows `current_taken`,
   `catch_up_taken`, `carried_forward` and `cap_amount` on each garnishment line.

**4. Before the first payroll with a garnishment (HR)**

On each order that came with arrears, set `arrears_opening` (`update_garnishment` or the Desk form). If the order
sets its own arrears payment, set `arrears_per_period` too. Set `consumer_debt` on Washington consumer-debt
judgments.

Then, after each saved run:
- every order's ledger gets a line, which `get_garnishment` and `get_payroll_deduction` show under `arrears`;
- the register (`get_payroll_register`, HR roles) lists who, which order, the amount taken, the cap and the
  arrears left.

**Rollback**

Roll back to the v0.291.0 image. The new tables stay but go unused. Under v0.291.0 a shortfall is reported but not
carried forward.

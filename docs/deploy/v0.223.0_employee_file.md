# Deploy: v0.223.0 — the Employee file; login cards never filed permanently

Rides on v0.222.1. Code plus one migrate (settings, a field on Mobile Access Grant, a patch, an hourly
job, a Client Script and Connections on Employee). App 0.31.0 for the phone view.

1. Build at `__version__ = "0.223.0"`; `bench migrate`; restart workers.
   - The patch prints how many filed login cards it deleted (expired, used, or superseded more than a
     week ago) and how many grants it linked to their Employee.
   - The Employee form gains an **Employee file** button and an **Employee file** Connections group.
2. `generate_mobile_login_qr` with `archive=true` is now refused. With device keys on, use
   `issue_enrollment_link`. In legacy mode, tick **File login cards** only if a camp office truly needs
   a printed copy; it deletes itself on first sign-in or at expiry.
3. Check one person: Employee → **Employee file** (or `get_employee_file`). Expiring and expired items
   are at the top. Adjust **Expiry warning windows (days)** if 90/60/30 days are not right.
4. Audit packet: Employee file → **Export audit packet** (HR Manager / System Manager). The PDF lands
   in the Employee's attachments, private. `allow_export_employee_file_packet` stays off unless an AI
   client should do it.
5. Phone (0.31.0): My records → My file; a manager: Employees → a person → File.

# Deploy: v0.227.0 — punch times from phones with no signal (app 0.34.0)

Code plus one migrate (new columns on Farm Shift Crew Member and Training Session Attendee; one
setting; two tool switches; one manager tile). Passive until a phone sends `tapped_at` (app 0.34.0) —
the crew clock's existing `joined_at` / `left_at` are now stamped the same way.

**Test on umbrel.local only.** Not OML.

1. Build at `__version__ = "0.227.0"`; `bench migrate`; restart workers. Ship app 0.34.0.
2. Check the migrate: a crew row and an attendee row each have a collapsed **Phone and server times**
   section; ERPNext MCP Settings has **Offline window (hours)** = 12. The **Punch times to review** tile
   appears on Today for Farm Manager / HR / System Manager (empty until something is flagged).
3. Test: phone in airplane mode → Work → Clock in crew (starts a shift) → wait, or set the window to
   0.05 h for the test → back online. The shift starts and the crew joins at the **tap** time; the row
   shows both times; past the window it is flagged and the tile counts it.
4. As a manager: open the tile → choose **Phone time stands**, **Server time used**, or **Corrected**
   (MCP: `resolve_punch_review`, switch off by default). The phone's time and the server's time stay on
   the row either way.
5. Same for a class check-in (Today → class card → Check in) made with no signal.
6. Set the window for real: **Offline window (hours)** (12 suits a day in the block synced that
   evening; Mill Creek crews that sync next morning may want 24).

**Settings**: `offline_punch_window_hours` (12), `allow_list_punch_reviews` (on, read),
`allow_resolve_punch_review` (off).

**Behaviour change to note**: a Clock in crew that has to start a shift now starts it at the tapped
time, not at sync time — before this, an offline clock-in synced later refused everyone as "before the
shift started".

**Rollback**: additive columns; an older build ignores them.

# Deploy: v0.229.0 — ending a shift, running a class and reporting a problem with no signal (app 0.36.0)

Code only — **no migrate needed** (no new columns; receipts are audit rows). No settings.

**Test on umbrel.local only.** Not OML.

1. Build at `__version__ = "0.229.0"`; restart workers (`bench migrate` is harmless but not required). Ship
   app 0.36.0.
2. Prepare for offline as a Foreman: the line now also says how many badges came down (the crew clock and the
   class door name people they scan with no signal).
3. **End a shift offline**: open a shift with signal, clock a crew in, airplane mode, clock one out, then Close
   Shift → sign. The phone says the close is saved; Settings → Waiting to sync shows the clock-outs, then the
   Shift close. Back online they send in that order; the Desk shows each left_at at the tap time and one
   Attendance row each. Toggle signal mid-send: a resend answers `replayed` — no "already closed" refusal, no
   second set of rows.
4. **Run a class offline**: open a class with signal, airplane mode, scan badges at the door (rows appear
   "Saved on this phone"), take signatures, Complete. Force-quit and reopen the class: the rows are still
   there. Back online: attendees, signatures, then completion, in order; training records filed.
5. **Report a problem offline**: scan → Report a problem with a photo → "Saved on this phone". Back online:
   one Farm Task in the pool with the photo and `observed_at` = when it was seen. A resend is the same task.
6. Task list and Housing list with no signal show the last saved copy with "as of".

**Server changes**: `client_request_id` (same request → same answer, `replayed: true`) on `end_shift`,
`clock_out_worker`, `add_session_attendee`, `sign_session_attendance`, `complete_training_session`,
`report_field_task`; receipts are MCP Action Log rows (`once:<method>:<user>:<id>`).
`get_offline_scan_pack` adds `badges` for Foreman / Crew Leader / Farm Manager / HR.

**Rollback**: nothing to undo on the server. App 0.36.0 against an older server: resends of these writes can
be refused ("already closed") and wait in Settings with Retry.

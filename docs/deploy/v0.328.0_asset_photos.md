**Deploy: v0.328.0 — task photos on the asset (linked, not copied), asset → task history, photo gallery, EXIF kept, housing value (with FarmOps 0.68.0 (64))**

**Migrate**:
- Farm Task Evidence gains `for_asset` and `asset`;
- Farm Task `location` and Farm Task Location `location` are indexed;
- ERPNext MCP Settings gains `asset_photo_task_types` (default Inspection / Maintenance / Repair).

Tools: **1,153 → 1,153**. There is no new tool. `update_registered_asset` gains `link_task_photos`; `get_asset_detail`, `scan_asset`,
`universal_scan`, `get_farm_task`, `create_housing_unit`, `update_housing_unit` and `get_housing_unit` gain fields.

**Why** (Tim's camp-buildings insurance report, 2026-10-13)
- MC-SHOWER-TOILET-1 showed no tasks, though FT-2026-10-00013 photographed it. The asset screens read `task.asset` and
  open tasks only, and the insurance tasks name their building as the task's location.
- The side photos stayed on the assignments. 20 were attached to the assets by hand on 10/13, and the server
  re-encoded each copy (different checksums, about 10 MB extra).
- None of the 144 photos keeps GPS or a capture time. Frappe's System Setting "Strip EXIF tags from uploaded images"
  (default on) re-encodes every JPEG on save, after the phone has hashed it. Confirmed on FT-2026-10-00015's photo:
  no EXIF block, and a sha256 different from the phone's.
- Tim's 25 cabin values (10/11–12) were shown on the phone form and dropped by the route.

**What changed**
1. **Asset → task history** (display only):
   - `get_asset_detail`, `scan_asset` and the phone asset screen show `task_history`;
   - `universal_scan` shows `asset_history`;
   - the Desk Asset Register form gets a "Tasks & photos" section;
   - every task about the asset is listed, open or done, whether found by `asset`, location, a multi-place row or
     the cabin, with state, the task and assignment, and a photo strip.
2. **Photo gallery on the Farm Task** (display only): the Desk form shows a "Photos" section, `get_farm_task` returns
   `gallery`, and the phone `get_task` returns `evidence_gallery`. Every assignment is shown, each photo labeled by
   step, before / after, time and place.
3. **EXIF kept:** task, asset and inspection photos are stored as uploaded, with GPS, time and lens. Employee, I-9,
   W-4, injury and badge photos are still stripped. The site setting itself is unchanged.
4. **Side photos linked to the asset at completion:**
   - one set of bytes, shown on both, as a second File row with the same file_url and content_hash, so deleting
     either row keeps the bytes;
   - named `<ASSET>_<SIDE>_<date>`;
   - only photos tagged to a checklist step or marked "attach to asset" (phone 0.68.0);
   - never signatures, before photos or untagged extras, and only for the task types in `asset_photo_task_types`;
   - on a multi-place task, the photo's own asset;
   - idempotent.

   This replaces v0.326.0, which filed every evidence file (signatures too) on `task.asset`.
5. **Backfill, reviewed:** `update_registered_asset link_task_photos=true`.
   - Scope: `asset_name=<asset>` takes that asset's tasks; `asset_name='*'` takes `tasks=[…]` or `since=…`.
   - **Dry run by default:** the links it would make, what it skips and why, and the hand-attached
     `<ASSET>_<SIDE>_<date>` copies whose bytes are not a task's.
   - Applying it notes each run on the asset's timeline.
   - `replace_manual=true` (with `dry_run=false`) deletes a re-encoded copy only where the asset now has the linked
     original for that side.
6. **Housing value:**
   - `create_housing_unit`, `update_housing_unit` (MCP and phone) take `purchase_value`, `replacement_value` and
     `acquired_on`, filed on the cabin's Asset Register tag (the insurance schedule's record);
   - `get_housing_unit` shows `value`.
7. **No more silent drops:** a field the phone sends that a route does not take is an Error Log row, "FarmOps sent
   fields the farm does not keep — <route>", logged once an hour per route and field set.

The task's evidence rows and files remain the record of truth: nothing moves, renames or deletes them.

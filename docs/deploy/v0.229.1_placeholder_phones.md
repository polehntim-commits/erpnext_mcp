# Deploy: v0.229.1 — receipts resolved on a placeholder phone are repaired

Code only; no migrate. One new MCP tool, `repair_placeholder_phones`, **off by default**
(`allow_repair_placeholder_phones`).

**Test on umbrel.local only.** On OML it is Tim's call: the tool is a dry run unless `apply` is true, so
the dry run is a safe read.

1. Build at `__version__ = "0.229.1"`; restart workers.
2. Tick **Repair Placeholder Phones** in ERPNext MCP Settings, then call `repair_placeholder_phones` with no
   arguments. It lists every Expense Receipt whose stored phone is filler (0000000000, one digit repeated,
   1234567890…), with its resolution before and after. On OML expect EXR-2026-0015 to move from Sawyer's
   Hardware Llc (Phone, 0.83) to its domain or printed name (Coastal), and EXR-2026-0014 to lose its zeros.
3. If the list is right, call it again with `apply: true`. The zeros are cleared and the resolution is
   rewritten. A Manual / LLM / Alias answer is kept (only the phone is cleared). **The supplier link is
   never changed** — where it disagrees with the new answer the row carries `supplier_note`; fix those by
   hand in the Desk.
4. Untick the switch.

New captures already dropped placeholder phones (v0.183.0 / v0.190.0); this release repairs the rows
resolved before that, and stops a re-resolved receipt from counting its own supplier link as evidence.
